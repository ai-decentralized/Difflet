# HunyuanVideo 1.0 on neuron: what to reuse from which model

Survey of every model on the neuron backend at bda3dde (Flux, Wan, Qwen-Image, LTX-2, HV1.5, shared core/CLI); 77 direct-reuse claims adversarially checked, none refuted outright. Plan amendments derived from it: docs/superpowers/plans/2026-10-24-hunyuan-video-neuron.md (A1-A9).

## 1. How each model enables neuron

**Flux.** Wraps Difflet's own backend-neutral DiT (`models/flux/modeling_flux.py`) in `NeuronFluxTransformerApplication(TorchNeuronApplicationBase)` (`backends/neuron/flux/transformer.py:52`). The checkpoint mapping is a regex (`:30-39`) plus `CheckpointSlice` on the fused single-block `proj_out` (`:78-85`). The composed app `TorchNeuronFluxApplication` (`models/flux/neuron_application.py:116`) does not use `TorchNeuronModelApplication`; it runs diffusers' `FluxPipeline.__call__` with plain adapters. The registry routes neuron at `models/flux/entry.py:19-25`. Text encoders: T5 TP on the device, CLIP on every rank's host. VAE: 2D, fp32, eager, one core. CLI (`cli/orchestrators/flux.py:113-330`): a hand-written `transformer` torchrun stage, then a one-core `vae` stage. It has no stage manifest and does not use `run_generate_stage`.

**Wan.** Wraps Difflet's own DiT in `NeuronWanTransformerApplication` (`backends/neuron/wan/transformer.py:47`), with config `NeuronWanConfig(WanTransformerConfig)` (`wan/config.py:39`) whose validation is built from `core/config_checks.py`. The composed app `TorchNeuronWanApplication(TorchNeuronModelApplication)` (`models/wan/neuron_application.py:257`) goes through the registry (`entry.py:30-44`). umT5 runs on the rank-0 host (`HostTextEncoder`) or TP on the device. The VAE runs fp32 eager on one core, either in-app or in a separate stage. It keeps TeaCache with `TEACACHE_KWARGS=()` and a `NeuronTeaCacheProbe` per expert. CLI: `run_generate_stage`, then `run_vae_stage`, keyed with `torchrun_stage_keys` (`wan.py:452,560,614`).

**Qwen-Image.** Wraps Difflet's own trace module plus a CFG subclass that exists only on neuron (`qwen_image/transformer.py:66-133`), and does CP inside the modeling. The composed app subclasses `TorchNeuronModelApplication` (`models/qwen_image/neuron_application.py:420`) through the registry. Qwen2.5-VL runs on the rank-0 host by default; a TP device encoder is opt-in. The VAE is Wan's, decoded on the host or in a one-core stage. TeaCache is refused. CLI: the text encoder is folded into one torchrun `generate` stage (`qwen_image.py:730`), followed by a host or `vae` decode, with keys from `torchrun_stage_keys` (`:922`) and driver-side `dit_fits`.

**LTX-2.** Wraps Difflet's trace module in a lazily built subclass that adds host RoPE, a CFG split and CP processors (`ltx_2/transformer.py:131-338`). Config is a dataclass (`ltx_2/config.py:43`). The composed app subclasses `TorchNeuronModelApplication` (`models/ltx_2/neuron_application.py:376`) through the registry. Text encoding uses diffusers' `LTX2Pipeline` on the rank-0 host, with a discarded warm-up encode; Gemma3 on the device is opt-in. The VAE decodes on the host by default (`_DEVICE_VAE_DEFAULT=False`), with `--device-vae` as an opt-in. TeaCache is refused. CLI: a `generate` stage via `run_generate_stage`, then a host decode or `run_vae_stage`, with `torchrun_stage_keys`, plus `refuse_dit_overflow` before launch.

**HV1.5.** Wraps diffusers' `HunyuanVideo15Transformer3DModel`, because no Difflet port exists. TP, CP and SP are added by module surgery and custom attention processors (`hunyuan_video15/transformer.py:244-462`). It bypasses the registry and the composed base, and has its own true-CFG loop (`hunyuan_video15/pipeline.py:58`). Text encoding: diffusers `encode_prompt` in a host `encode` stage. VAE: diffusers, tiled, eager, one core (`vae.py:209`). CLI (`hunyuan_video_15.py:65`): `encode`, `transformer`, `vae` via `runner.run_stage`, with no stage keys and the NKI trace-cache opt-in (`:95-108`).

## 3. Plan alignment

**Already uses the best source**
- Task 1 has `tp_degree` in its config, so the CP mesh re-init bug is avoided. It uses the `config_checks` helpers and `dit_fits` on top of `hbm.Component`.
- Task 2 matches the verified CPU prototype: the port inside `TorchNeuronApplicationBase`, both `block_attrs`, a `return_dict=False` tensor-signature subclass (avoids the `OnDeviceDiT` crash on `Transformer2DModelOutput`), `CheckpointSlice` plus the bias rename.
- Task 3 is right to expect no code: gather_kv, ulysses and SP already match on gloo.
- Task 4's ring fix is the HV1.5/neuron-op approach (`text_valid_len`, fp32 count).
- Task 5 builds on `TorchNeuronModelApplication` with `TEACACHE_KWARGS=()`, a rank-0 diffusers `encode_prompt` (verified equal to the AoT layers.29 + crop 95), `_draw_on_rank0` and `output_type="latent"`.
- Task 6 uses the HV1.5 VAE pattern. Task 7 uses `run_generate_stage`, `run_vae_stage`, `torchrun_stage_keys` and `refuse_dit_overflow`. Task 8 uses the HV1.5 two-phase 1.15× gate.

**Re-implements something reusable, or gets it wrong**
- **Task 5, TeaCache.** It uses `NeuronTeaCacheProbe` unchanged, which computes rel-L1. The HV calibrations need L2. Subclass it and override `teacache_delta` to L2. Also call `probe.reset()` in `generate()`. The plan cites `pipeline.py:220-226`; the fused branch is at `:230-255`.
- **Task 5, adapter.** `_forward` casts the int64 mask to bf16. Override it the way HV1.5's `_positional` (`hunyuan_video15/transformer.py:144`) does, so the mask stays int64 and matches the warm-up dtypes.
- **Task 5, host encoder.** The plan does not mention `warmup_args`. Copy the LTX-2/Qwen discarded first encode, which works around the bf16 first-encode nondeterminism.
- **Task 2, `checkpoint_key`.** The plan writes its own copy of Flux's `flux/transformer.py:35` regex. Import it, or hoist key + slices into `core/checkpoint.py`, and Flux and HV share one helper.
- **Task 5, shape check.** The plan writes a new one. `_check_dit_shapes` (Qwen `:381`, LTX-2 `:354`) is the pattern to copy. `validate_hunyuan_video_dit_inputs` (`application.py:138`) would also work if the config gained a `neuron_config` property, which the committed config lacks.
- **Task 7, flags.** "TeaCache flags forwarded" needs the explicit `--teacache*` filter on `torchrun_unsupported_options` (`wan.py:257`), or the shared refusal blocks them.
- **Task 7, VAE default.** The plan makes the vae launch the default and `--host-vae` conditional. LTX-2 does the opposite: host decode is the default, because the extra launch cost more than the device decode saved. Decide which default to use from a measurement.
- **Task 8, scripts.** The new check scripts should import `tests/numerical/neuron_parity.py` (`run_parity`, `check`, `device_evidence`, `_cast`) and `neuron_benchmark.py` rather than re-deriving the metrics.

**Reusable things the plan misses**
- **Truncated-depth parity.** `config_checks.truncated_block_prefixes` (`:157`), called once per stack, plus `checkpoint_num_*` fields on the config, which the committed config lacks. This makes N-block device parity fast and avoids the 52 GB fp32 oracle (pattern: `check_neuron_ltx2_preflight.py`, `check_neuron_wan_preflight.py`).
- **Mask-bounds regression.** `tests/manual/check_hunyuan_video_mask_bounds.py`, re-targeted at `torch.compile(backend="neuron")`, guards the fp32 count against the LNC2 integer-reduction bug.
- **HBM headroom at TP2.** The replicated AdaLN linears put tp2 at 15.18 GiB per rank. If activations at 320×512×61 overflow, HV1.5 has the fix: column-parallel `norm1.linear` with gather (`hunyuan_video15/transformer.py:414`), about 3.2 GiB saved per rank. Plan Task 1's "÷ tp" estimate under-counts this; the base re-checks at load.
- **NKI trace-cache opt-in.** Same kernel as HV1.5 (`hunyuan_video_15.py:95-108`, `compile.py:65`). The gain is smaller at about 10.5k tokens.
- **Contingency if the device gate fails.** `Fp32GELU.from_gelu` (`core/activations.py:35`) for `ff.net[0]`. `use_fp32_gelu` is a no-op for `HunyuanVideoGELU`, and the single blocks' bare `nn.GELU` needs its own wrapper.
- **Test doubles and cases.** `tests/unit/cli/_fake_neuron_pipeline.py` needs an HV fake. LTX-2's header-only safetensors HBM refusal test (`test_ltx2_neuron_cli.py:133`) covers the tp1 refusal without weights.
- **Benchmark harness.** The observer probe on `_scheduler_step` plus `step_hook` (`ltx_2_neuron.md`). The `benchmark/models.py:178` HV BenchConfig, with steps and tp set for neuron.
- **Registry `cp_modes`.** Until Task 4 lands, the capabilities advertise ring while the modeling raises. Keep Task 1's validate refusing ring until then, or land Task 4 before exposing the CLI.

## 4. Looks reusable but isn't

The checker marked no claim outright wrong. These claims were downgraded:
- Wan's "TeaCache probe import-as-is": the metric (L2) and the bundle arity differ.
- LTX-2's "toy import-as-is": only `run_ranks` and the generic helpers import as-is.
- Qwen's "QwenTextEncoderModel bit-exact": it only holds with random biases; the real HV checkpoint has no q/k/v bias.
- LTX-2's "HV supports ring": not until the modeling change lands.
