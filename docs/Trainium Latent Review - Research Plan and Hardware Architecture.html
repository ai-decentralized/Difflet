Executive SummaryTL;DR

— Three sentences —
  • 计划合理，但目前与 Trn3 硬件耦合不足。 "Latent runtime" 这一 framing 要在 MLSys/ASPLOS 上立住，必须围绕三个在 GPU 上没有干净对应物的 NCv4 原语重新设计：nc_matmul_mx + QuantizeMX（硬件 MXFP8/MXFP4，32-元素 microscaling 分组）、新增的 Vector Engine 快速 exponential 指令（Scalar Engine softmax 的 4× 吞吐）、以及 20 个 CC-Core + NeuronSwitch-v1 all-to-all fabric（通过 nki.collectives 暴露）。没有这些，审稿人只会看到 "Trainium port of TeaCache + xDiT"。
  • 最有辩护力的单一贡献是 candidate-axis 并行 + decode-free latent 世界模型规划。 V-JEPA-2-AC 在单卡 RTX 4090 上 16 秒/动作（800 候选样本）；同等任务下 Cosmos 像素空间 4 分钟/动作（80 样本 × 10 次精化）。把这个 workload 的 N-candidates × T-rollout × HW-latent 张量映射到 Trn3 的 [partition × LNC-rank × chip] 层次——配合 nki.collectives.all_to_all_v 做候选重分布、用 nki.isa.nonzero_with_count + oob_mode.skip DMA gather 做 top-k compaction——在 Trainium 上确实新，并利用了 H100 拿不到的 Trn3 特性。
  • 真正的项目风险不是硬件——是 NKI 对视频模型的成熟度和 NCv4 文档缺口。 你有 Trn3 直接访问意味着 LNC=2 多核 kernel、nc_matmul_mx、quantize_mx、nki.isa.exponential、oob_mode.skip SWDGE、all_to_all_v 都可以从 Day-1 在目标硬件上测——不需要前向兼容 fallback、不需要 nc_version 守门。剩下的不确定性是 (a) NKI tracer 是否接受 3D causal Conv / temporal attention / AdaLN modulation 的视频模型 pattern，(b) Conv3D NKI kernel 缺位（NKI Library 只有 Conv1D）需要自己分解或写，(c) SBUF/PSUM 间接寻址和 Activation2 在 Trn3 arch guide 描述了但 NKI 0.3.0 还没暴露 API，(d) HBM 带宽数字在 primary doc 中不一致（4.7 vs 4.9 TB/s）。这些都是工程问题，不是访问问题。

下一阶段最有价值的切入点不一定是再造一个 latent world model，而是构建一个面向 accelerator 的 latent-space runtime——但这个 runtime 必须深耦合到 NCv4 微架构，否则不过是 GPU 论文的 Trainium 移植。

01

Headline InsightsKey Findings

Trn3 / NCv4 的本质不是"更多 flops"，而是新原语。 Tensor Engine 是物理 128×128 PE array，但对 MXFP8/MXFP4，每个 PE 每周期 4 个 MX MAC，呈现给程序员的是 逻辑 512×128 systolic array——一条指令完成 M=128, K=512, N=512。SBUF 每核 32 MiB。Vector Engine 有硬件 exponential（自带 fused max-subtract-exp-accumulate；softmax 友好）和 QuantizeMX（TensorE 直接消费的 MXFP8 tile）。这些原语决定了 latent runtime 的设计空间。

20 个 CC-Cores/chip + NeuronSwitch-v1 all-to-all 拓扑。 Trn3 chip-to-chip 是 switched all-to-all 设计——一个 Trn3 Gen2 UltraServer 在 144 chip 上汇总 706 TB/s HBM，等价于 1-hop all-to-all；H100 NVL 超出 8 GPU 必须走 NVSwitch + InfiniBand。这是 collective-heavy workload（候选轴并行、MoE-style 路由、expert-routed VAE）的最大硬件杠杆。

NKI 0.2.0 引入 LNC=2 多核 kernel；NKI 0.3.0（Neuron 2.29.0，2026-04-09 发布）加入了 candidate-aware runtime 真正需要的原语——variable-length all-to-all（all_to_all_v）、nki.isa.exponential、nonzero_with_count、oob_mode.skip DMA、matmul accumulation 控制、Trn3 DMA 优先级、NKI 标准库、CPU 模拟器。Top-K Reduce kernel（原本服务于 MoE 输出聚合）和 find_nonzero_indices 恰好是 candidate-aware latent runtime 需要的——但仍是 experimental，且未针对视频 shape 调优。

GPU 端 DiT inference acceleration 已经非常拥挤——TeaCache、FasterCache、EasyCache、Δ-DiT、SpeCa、xDiT/PipeFusion/DistriFusion、FastVideo Sliding Tile Attention、Sparse-VideoGen 1/2、SVDQuant/Nunchaku。把这些纯移植到 Trainium 不会通过 MLSys 审稿。计划必须押注 GPU 做不好的事情：(a) 硬件 microscaling、一条指令 K=512；(b) 近内存 SBUF accumulation（DMA 做 B+=A，v4 之前只有 50% 带宽）；(c) oob_mode.skip SWDGE——单条 descriptor 编码"如果被剪枝就跳过"；(d) 通过 no_reorder 实现的确定性指令调度。

已发表的最接近 Trainium NKI 论文是 NeuronMM（arXiv 2510.25977）。 它通过 SVD 压缩 + "SRAM-capacity-aware caching strategy"（TrainiumFusion）显式利用 partition-dimension / SBUF / PSUM 层次，加速 LLM matmul。这篇 + ASPLOS 2025 NKI Tutorial / 竞赛（corelab-src/nki-llama 第 3 名）+ AccelOpt（arXiv 2511.15915，LLM 驱动的 NKI 优化）共同定义了"发表门槛"：深架构推理 + 相对 AWS 出厂内核的实测加速 + roofline 峰值占比。TrainiumLatent 应瞄准同一门槛。

视频扩散在 Trainium 上目前服务能力极差。 NxD-Inference 支持 Flux.1-dev（TP + CP + CFG-parallel）——但 Flux 是纯图像。没有公开的 HunyuanVideo / CogVideoX / Wan / Mochi / Open-Sora / Cosmos 的 Trainium reference。Month-1 MVP 比原计划想得重得多：把 3D causal VAE（Cosmos 风格的 Haar wavelet + causal Conv3D）、3D RoPE、3D full attention、AdaLN modulation 在 NKI/torch-neuronx 上跑通本身就是一个贡献（也很可能是 Build-on-Trainium 资助的交付物）。

Trn3 直接访问 = 稀有的研究平台机会。 当前公开发表的 Trainium NKI 论文只有 NeuronMM（LLM matmul）和 AccelOpt（LLM 通用 kernel 优化）；Trainium 上没有任何视频/世界模型公开工作。Trn3 容量当前主要被 Project Rainier（Anthropic）占用，绝大多数学术团队只能通过 Capacity Block 间歇访问。你已有 Trn3 dedicated access 意味着可以在硬件 microscaling matmul + NeuronSwitch-v1 all-to-all + Vector-Engine fast exp 这些没有任何外部论文测过的特性上做首次系统性测量。Build on Trainium Spring 2026 CFP（Kernels for ML Acceleration，2026-05-06 截止；Post-Training）仍值得申请——AWS credit + 论文+开源是它的标准要求，与你的发表路线天然对齐。

NCv4 MicroarchitectureTrainium3 Deep Dive

权威 primary source：Trainium3 Architecture Guide for NKI、NeuronCore-v4 文档页、Trn3 instance architecture 页面。每 chip 规格：

  • 8 NeuronCore-v4 cores；4 stacks HBM3e，144 GiB。NKI 文档写 4.7 TB/s，Trn3 instance 页和 AWS 公告写 4.9 TB/s——primary source 之间存在不一致，引用时两个都标。
  • 128 DMA engines，20 CC-Cores，4 NeuronLink-v4 ports/chip。
  • 每核：32 MiB SBUF（v3 是 28），2 MiB PSUM（不变），128 partitions。128-partition 约束没变；nl.tile_size.pmax = 128 的所有规则仍适用。

NCv4 的核心原语（论文 Section 3 的硬件 cheat sheet）

  1. 硬件 MXFP8/MXFP4 microscaling matmul（nc_matmul_mx）。 物理 PE array 仍是 128×128，但 MX 操作数每 PE 每周期 4 个 MX MAC，逻辑视图变成 128 行 × 512 K systolic array。Scaling group size = K 方向 32 个元素（8 partition × 4 element 共享一个 8-bit scale）。一条指令 M×K×N = 128×512×512。
  2. QuantizeMX（Vector Engine）——一条指令把 BF16/FP16 量化成 TensorE 可消费的 MXFP8 layout，4× Vector perf mode。
  3. nki.isa.exponential 在 Vector Engine——fused max-subtract + exp + accumulate；Scalar Engine exp 的 4× 吞吐。原话："a new instruction to perform fast exponential evaluation, at 4x the throughput compared to nisa.activation (op=nl.exp) on the Scalar Engine." 显式为 attention softmax 设计。
  4. BF16 PSUM writes + BF16 PSUM accumulation——matmul 输出可直接落到 BF16（内部 FP32 累加；下转时 RNE 或 stochastic rounding）。在 attention pipeline 中省一次 PSUM→SBUF copy。
  5. Background Transpose——TensorE 可以与另一个 matmul 并行跑转置；自动，无 API；在转置密集链路上吞吐翻倍。
  6. 近内存 SBUF accumulation（DMA B += A）——DMA engines 在 SBUF 上以全 DMA 吞吐做 read-add-write（v4 之前用 CC engine 只有 50%）。BF16 和 FP32 支持。对 diffusion residual stream 至关重要。
  7. SBUF/PSUM 沿 free dim 的间接寻址——计算引擎（TensorE/VectorE/ScalarE/GpsimdE）可直接做 gather/scatter。NKI 0.3.0 仍无 nki.isa API——记为 "near-future capability" 风险。
  8. DMA Traffic Shaping——4 classes of service 做细粒度 DMA 优先级。NKI 0.3.0 release note 提到 "DMA priority settings for Trn3" 但还没完整 QoS API。
  9. Activation2 指令——Scalar Engine；支持 bias subtraction、可选 scale/bias 关闭、add/max/min/absmax/absmin reduction。暂无 nki.isa API。
  10. Scalar Engine 2× perf mode（BF16/FP16 tensor_scalar / tensor_copy）——可以选择 ScalarE 或 VectorE 来做这些操作（VectorE 也有对应的 2× mode）。
  11. XORWOW 硬件 PRNG（VectorE）——4× 32-bit PRNG/周期/lane，通过 nisa.rand2 暴露。对 stochastic rounding 和 diffusion 的 on-device 噪声采样有用。
  12. NeuronSwitch-v1 all-to-all fabric。Switched all-to-all 拓扑是 collective-heavy workload 的最大硬件杠杆。
  13. PCIe Gen6 x8 server 内（256 GB/s bidir/chip）和跨 rack（128 GB/s bidir/chip）——PCIe 现在是 fabric 的一部分，不只是 host bus。
  14. LNC modes：NKI 0.2/0.3 示例展示 LNC=2。第三方报道（SemiAnalysis）说 Trn3 Day-0 支持 LNC=1 / LNC=2，LNC=8 延期到 2026 年中——primary doc 未确认。

Programming ModelNKI Current State

NKI 0.3.0（Neuron 2.29.0，2026-04-09 发布）是要瞄准的版本。来自官方 release note 的、对本计划有意义的亮点：

  • nki.collectives 模块：all_reduce、all_gather、reduce_scatter、all_to_all、all_to_all_v（variable-length，2.29 新增）、collective_permute 及隐式变体、rank_id、ReplicaGroup。SBUF 张量支持 2D 单 free-dim shape 的 collective；多张量 coalesced collective 只能在 HBM 上。
  • nki.isa.exponential（Vector Engine fast exp）和 nki.isa.nonzero_with_count（稀疏计算 / 动态掩码）——两者都是 2.27 加入。
  • nki.isa.quantize_mx——BF16/FP16 → MXFP8，输出是 TensorE 可消费的 layout。
  • nki.isa.nc_matmul_mx——仅 row-tiling PE tiling（无 column tiling）；data 接受 float8_e5m2_x4、float8_e4m3fn_x4、float4_e2m1fn_x4；scale 是 uint8；PSUM 输出 BF16 或 FP32。
  • Matmul accumulation 控制——nc_matmul 显式 accumulate=True/False/None。K-tiling 的确定性和 residual + matmul 融合的关键。
  • no_reorder 块——指令顺序控制。
  • DMA dma_copy 的 unique_indices 参数和 oob_mode.skip——把 SWDGE 变成真正的 gather/scatter（剪枝索引 no-op）。这就是让 latent compaction 高效的原语。
  • CPU 模拟器——无 Trainium 硬件也能本地开发 NKI；NKI 标准库以 Apache-2.0 开源。
  • NKI Library 生产内核：Attention CTE（≤131K seq，≤batch-512 with sequence packing）、Attention TKG / Attention Block TKG（QK-norm-before-RoPE fused、KVDP attention sharding）、MLP（MXFP4/MXFP8 quant paths、FP16 TKG、gate/up clamping）、MoE CTE + MoE TKG（dynamic all-expert algorithm、LNCShardingStrategy enum）、Output Projection CTE/TKG、QKV（fused FP8 KV-cache quant、block-based KV cache）、RMSNorm-Quant、RoPE、Router Top-K、Cumsum、Top-K Reduce（MoE 输出聚合，LNC sharding）、Transformer TKG（多层 token-generation megakernel）、Fine-Grained All-Gather、FGCC（All-Gather + Matmul fused）、SBUF-to-SBUF All-Gather、Conv1D、find_nonzero_indices、Dynamic Elementwise Add。

已知限制（视频依然痛）

  • 编译流水线是 NKI → NEFF（MLIR-based NKI compiler → Neuron Graph Compiler）。NKI 是 tile-level DSL，不是任意 PyTorch tracer；仍要在 Python 里用 @nki.jit 写 tile。NCC 对 stablehlo.while 的约束（用户已遇到过）仍需要 dynamic_range + VirtualRegister cond，活的 SBUF 张量被 pin 整个 loop。Diffusion 采样循环的实用 workaround 仍是用 static_range / affine_range / sequential_range 静态展开，或 host-driven step + input_output_aliases 持久化状态。
  • 任意 shape 的 2D-strided DMA 副本路径不通——DMA stride mismatch 仍需走 SWDGE fallback 或 dma_transpose（2.27+ 支持间接寻址）。
  • 0.3.0 仍无公开的 Conv3D 或 3D causal Conv NKI kernel（NKI Library 只有 Conv1D）。要么用 tile decomposition 把 Conv3D 拆成 Conv2D/Conv1D 序列，要么自己写 fused Conv3D——后者如果泛化得好，本身就是一篇贡献。
  • nki.collectives 的 SBUF mode 受限于 2D 单 free-dim 张量；多张量 coalesced collective 需要 HBM。候选轴 collective 要小心规划。

候选轴 [B, N, T, H, W, C]（B=batch、N=候选数、T=帧、H/W=空间、C=channel）是"latent runtime"有趣的根源：世界模型用 cross-entropy method 做 MPC 时，V-JEPA-2-AC 用 800 sample × 10 次精化 × horizon 1 在单卡 RTX 4090 上达到 16 秒/动作；同任务 Cosmos 像素空间 4 分钟/动作（80 sample × 10 次精化 × horizon 1）。N 区间因此是 32 到 ~1000，T 是 1–16。

Top-k / gather-scatter / compact 现状

Prior ArtLatent Runtime — The Gap Map

Caching（training-free）

TeaCache（Liu et al. 2024, arXiv 2411.19108; CVPR 2025）："up to 4.41× acceleration over Open-Sora-Plan with negligible (-0.07% Vbench) degradation"，单卡 A800，16-帧 512×512。FasterCache（1.67× Vchitect-2.0, arXiv 2410.19355）；EasyCache（Zhou et al. 2025, arXiv 2507.02860）："improves speedup over TeaCache by 36% while boosting PSNR by 37% and SSIM by 14%" on HunyuanVideo。Δ-DiT（1.6× PIXART-α / DiT-XL, arXiv 2406.01125）、AdaCache、SmoothCache。

Sparse attention

STA / FastVideo、Sparse-VideoGen 1/2、RainFusion、Sparse-vDiT、MInference——全是 GPU，全是 H100-specific kernel。

Quantization

SVDQuant + Nunchaku（Li et al. 2025, arXiv 2411.05007; ICLR 2025 Spotlight）："On 12B FLUX.1-dev, 3.6× memory reduction vs BF16. By eliminating CPU offloading, 8.7× speedup over 16-bit on a 16GB laptop 4090 GPU, 3× faster than NF4 W4A16 baseline." Q-Diffusion、ViDiT-Q（W8A8）、Q-DiT、DVD-Quant。SVDQuant 在 RTX 5090 上用 NVFP4（block 16, E8M0）——Trn3 不支持 NVFP4，只支持 OCP MXFP4（block 32, E8M0 scale + E2M1 data）。这是关键的协同设计点。

Parallelism

xDiT、PipeFusion（patch-level pipeline）、DistriFusion（async all-gather）、DistVAE、USP、CFG-parallel、ScaleFusion（MLSys 2025，ST-DiT，32 A100 上 3.60×）、PipeDiT（arXiv 2511.12056, 2025）。NxD-Inference 对 Flux 用 TP + CP + CFG-parallel——但没有 displaced-patch / temporal-redundancy 技巧。

Speculative / forecast

SpeCa（DiT feature 上 forecast-then-verify, arXiv 2509.11628）、Next-Frame Diffusion（action-input speculative sampling, A100 30+ FPS, arXiv 2506.01380）、HIPPO（video-LLM parallel speculative decoding）。

Decode-free latent scoring

V-JEPA-2 / V-JEPA-2-AC（冻结 encoder 上的 latent energy + cross-entropy method MPC，16 秒/动作 vs Cosmos 4 分钟）。Dreamer-V3 / Dreamer-4（latent imagination；Dreamer-4 在 H100 上实时交互，9.6 秒上下文，arXiv 2509.24527）。Genie 2（DeepMind 自回归 latent diffusion world model）、DIAMOND、MuZero、TD-MPC2。

真正的 gap 是 (latent caching + 候选轴并行 + decode-free scoring + 硬件 microscaling 感知量化) ∩ (non-GPU accelerator)。当前 Trainium 论文中没有任何一篇同时覆盖其中两个。

Hardware HooksTrn3-Specific Opportunities

这是原计划需要最大幅度修订的地方。具体映射：

  1. 候选轴 → LNC + chip rank。 把 [B, N] 映射到（intra-LNC NeuronCore rank × inter-chip rank），通过 nki.collectives.ReplicaGroup。Top-k 剪枝后用新的 all_to_all_v（variable-length，NKI 0.3.0）——每个 rank 剩下不同的存活数。
  2. Top-k 候选打分在 CC-Core 上。 现有的 Top-K Reduce NKI Library kernel（用于 MoE 输出聚合 + LNC sharding）和候选-top-k 在结构上完全相同。复用 + 针对 [N, score] 而不是 [E, output] 调优。
  3. Latent compaction 通过 SWDGE gather/scatter。 nki.isa.dma_copy(..., dge_mode=swdge, unique_indices=..., oob_mode=oob_mode.skip)——单条 descriptor 编码"对要保留的 N 个候选，从 HBM gather 它们的 [T,H,W,C] latent 到 SBUF；剪枝的索引跳过"。这在 Trn3 上根本上比 H100 简单——GPU 上通常需要 CUTLASS gather kernel stream + cudaMemcpy + compaction prefix-sum。用 nki.isa.nonzero_with_count 在片上算 keep-mask。
  4. MXFP8 / MXFP4 候选感知量化。 32-元素 MX group size 与典型 DiT head-dim 粒度对齐（head_dim 64, 128 → 每 head row 2 或 4 个 group）。在同一个 kernel里运行 Vector Engine 的 quantize_mx 输出 attention，下一层 K @ V 从 MXFP8 起步，零 HBM 往返。对比 SVDQuant W4A4：SVDQuant 必须有低秩分支吸收 outlier，因为它没有硬件 microscaling；Trn3 硬件 MX group=32 意味着简单的对称量化就能匹配它。这是最干净的"为什么要 Trn3"的故事。
  5. 通过 nki.isa.exponential 做 fused softmax。 4× VectorE exp 加上新的 BF16 PSUM write，让你能在单个 VectorE op stream 中发出 max-subtract-exp-accumulate——结果停留在 BF16 PSUM，立刻能消费给 V @ S matmul。这是 Trn3 对 FA-3 exp2 trick 的回答。
  6. Diffusion residual 的近内存累加。 每个 DiT block 都有 x = x + Attn(LN(x)) 和 x = x + MLP(LN(x))。新的 SBUF Read-Add-Write 以全 DMA 吞吐让你完全绕过显式 add kernel——residual 折进 PSUM→SBUF 的 DMA 回写中。
  7. 持久化 latent cache 通过 input_output_aliases。 鉴于 NCC 的 stablehlo.while 约束，diffusion 采样循环的常规做法是编译一个 single-step graph 并由 host 调度，通过 input_output_aliases 把 KV / feature cache 钉在 HBM。NxD-Inference 已经这么做；贡献是把它扩展到候选感知cache layout（[N, layer, T, H, W, C]，以 step + candidate index 为键）。
  8. 3D causal Conv via Conv1D + tile composition。 NKI 出 Conv3D 之前，把 Cosmos 风格 3D causal conv 分解为（时间 Conv1D，partition 维度上展开 T）×（空间 Conv2D，TensorE 上的 Toeplitz matmul）。这本身就是一个可发表的子 kernel。
  9. Attention 中的 Background Transpose。 Q/K 转置在 QK^T 设置里落在 PE-tiled background transpose 上，释放 TensorE 周期给真正的 matmul。
  10. 候选 pre-fetch 的 DMA traffic shaping。 用 4 个 DMA class 区分：下一 step 的 latent prefetch（高优先级）vs 后台 scoring 张量搬运（低优先级）。

C · Latent Cache 设计 — paged 风格 + 双层（SBUF / HBM）

把 vLLM paged attention 的设计模式移植到 latent runtime，但利用 Trn3 的双层显存：

  • Block 定义：1 candidate × 1 stage × 1 frame × [H, W, C] tile，典型 16 KiB–256 KiB。
  • Hot tier (SBUF)：当前 step 活跃的 top-k candidate。每 chip 256 MiB SBUF（32 MiB × 8 core）容纳 ~1000 个 256 KiB block；用 LNC=2 跨核 sharding 后单核 32 MiB 容纳 ~125 block。
  • Cold tier (HBM)：未来 step / 已剪枝但保留 lineage 的 candidate。144 GiB HBM 容纳 ~600K block。
  • Block table 在 HBM：block_table[N, stage] → (chip_id, hbm_offset)。
  • 剪枝后操作：不重排数据——只更新 block table，下次 access 时 SWDGE 用 oob_mode.skip + unique_indices gather。
  • Prefetch：4 个 DMA traffic class 把 "next step latent prefetch" 设为高优先级、"score tensor 移动" 设为低优先级，与 compute 重叠。

Per-candidate Adaptive Compute

Early-Exit Latent Rollout · 异步 dispatch

Paper A
System Idea

当前所有 candidate 跑完全部 denoising step。事实上多数 candidate 在中间就能判断"必败"——应该提前 exit。但 GPU 上 batched 执行让 early-exit 不收益：batch 里一个 candidate 没 exit，其它就要等。

Runtime-Adaptive Precision

Stage-Adaptive MX Scheduling · calibration-driven

Paper A
System Idea

原计划的 4D quantization matrix 是 hand-designed rule。换成 runtime 实测驱动——每个 stage 跑一个 µs 级 calibration probe，测当前 model + 当前 workload + 当前 stage对量化的敏感度，自动选 MXFP4 / MXFP8 / BF16。

核心是 decision cache：calibration 决策一次，cache 在 SBUF 跨所有 candidate 共享；每 K step 重新校准一次（K ≈ 4–8）。

Trn3 Arch Hooks
  • Calibration probe = 1 个 candidate forward step 用 MXFP4 vs BF16，比较 latent output
  • KL/L2 reconstruction error 计算：VectorE exponential + reduction，~10 µs
  • Decision cache：每 (stage, layer) 的精度选择存在 SBUF region，跨 candidate 共享读
  • Precision 切换 = compile 多版本 kernel（MXFP4 / MXFP8 / BF16），runtime dispatch 选其一
  • quantize_mx 调用代价 vs 跳过的对比 = 数据点本身
Calibration 信号：err(stage, layer) = ||z_BF16 − z_MX||₂ / ||z_BF16||₂。Pareto-frontier-aware 阈值切换：当 err > τ_high 升级精度，err < τ_low 降级精度。τ 取 calibration 集上 quality vs latency Pareto 曲线肘点。
论文价值：当前所有 SVDQuant / MXFP 论文都是静态量化（一次决定，全程不变）。这是runtime-adaptive——跨 model、跨 workload portable，不需要 per-model 调参。Trn3 的快速 calibration kernel + group=32 微调粒度是关键。

Paper A
System Idea

N candidate 在同一 diffusion step 跑 attention，QKV 矩阵很多列共享——因为它们共享 condition、共享 observation。Attention 的 K 和 V 投影是 shared parameters × shared input，应该算一次共享，而不是 N 次重复。

Trn3 Arch Hooks

System Idea

小 world model（draft，~1B）在 latent 中快速 rollout 多步；大 world model（target，~8B）在 latent 中跳跃 verify 关键 step——全程不出 latent space。Verify metric 是 latent 距离或 learned consistency head，跳过 decode。

这是 LLM speculative decoding 在 video diffusion 上的第一个完整搬移。SpeCa 是 feature-level；这是 model-level，是 Leviathan 2023 的直接对应。

Trn3 Arch Hooks
  • Draft model pinned 在 1 chip，SBUF-resident weights，BF16
  • Target model 跨 8–16 chip TP+CP，MXFP8
  • Draft → target 通过 NeuronSwitch-v1 all-to-all 路由 latent，不落 HBM
  • Verify 在 latent 里：VectorE 算距离 + 小 consistency head（TensorE）
  • Accept/reject 决定哪些 draft step 保留——异步分支用 oob_mode.skip
Speculative acceptance：α = min(1, p_target(z) / p_draft(z))——直接套 Leviathan-Kalman 2023 的公式，分布换成 latent likelihood（用 flow matching 的 log-prob，闭式可得）。
论文价值：LLM speculative decoding 在 video diffusion 上没有完整对应物。NeuronSwitch-v1 全互联是论文最强的 hardware story——144-chip Gen2 UltraServer 终于真正用满。

Multi-Fidelity Cascade

Hierarchical Latent Refinement · 跨分辨率不出 pixel

Paper B
System Idea

先在低分辨率 latent 上跑大量 candidate 粗筛（N=256, 16×16），top-k 后 lift 到高分辨率 latent 精修（k=8, 64×64）。中间不出 pixel 空间——learned latent_upsample 模型做跨分辨率桥接。

很多 video model 已是 cascaded（Stable Video Diffusion → SDXL Refiner；Cosmos 多档），但都是 pixel-mediated cascade。这把它变成 latent-only runtime primitive。

Trn3 Arch Hooks
  • Low-res stage：1 chip，LNC=2，MXFP4，N=256 candidate 全部装 SBUF
  • High-res stage：16 chip TP+CP，MXFP8，k=8 survivor，NeuronSwitch all-to-all 分发
  • Lift = ~10M params latent_upsample，SBUF-resident（每核 32 MiB 足够）
  • Stage transition 通过 NeuronLink-v4 直接传 SBUF——不落 HBM
  • 异构 chip group 调度：runtime API 暴露 low_res_pool / high_res_pool
Multi-fidelity 假设：Spearman ρ(rank_low_res, rank_high_res) > 0.85——低分辨率 ranking 与高分辨率 ground-truth 的相关性。如果实测 ρ > 0.85，cascade 就有效；否则降级为 high-res-only。这是 multi-fidelity Monte Carlo 在仿真社区的经典门槛。
论文价值：Multi-fidelity 在仿真社区是经典，但 accelerator runtime 上还没做。Trn3 是唯一能在单系统内做异构资源分配（小 chip group 跑低分 + 大 chip group 跑高分）的硬件——H100 集群没有这种"系统内异构 chip group"的概念。

System-Level 耦合：六个 Mechanism 不独立

六个机制不是独立 features，而是系统级互相依赖。下表是真正的耦合关系——这是 Paper A 与 Paper B 必须强调的："Trainium-aware latent runtime"不是 6 个 trick 的并集，而是 6 个机制围绕同一组 Trn3 原语（SBUF 层次 + NeuronSwitch all-to-all + quantize_mx + oob_mode.skip）协同设计的整体。

Defending Against the Reviewervs GPU Baseline

在 Trn3 上根本上更容易/便宜的事情

  • 指令内 microscaling，group=32，K=512 一条 nc_matmul_mx 完成——H100 只有 per-tensor FP8 scaling；B200 / RTX 5090 有 NVFP4（block 16, E8M0 scale）；但都不在 tensor core 内 native 支持 OCP MXFP8/MXFP4（block 32, E8M0 + E5M2/E4M3FN/E2M1FN）。Trn3 MX matmul 在一条指令内给 BF16 4× 加速 + 硬件 dequant。
  • 软件管理 SBUF（32 MiB × 8 core = 256 MiB/chip）——候选 KV / feature cache 可以确定性 pin 住；没有 H100 那种 L2-miss 抖动。
  • NeuronSwitch-v1 all-to-all 跨 144 chip——all_to_all_v 等价 1-hop；H100 NVL36 / NVL72 跨 rack 必须走 NVSwitch + InfiniBand。
  • oob_mode.skip SWDGE——单 descriptor gather 含跳过索引；CUDA 上需要 compaction + cudaMemcpyAsync + kernel launch 组装。
  • 近内存 SBUF accumulation（DMA 做 B += A）——H100 上没有等价物（最接近的是 TMA，仍需独立 add）。
  • TensorE 上的 background transpose——H100 用 shared-memory shuffle + warp-level transpose。

在 Trn3 上根本上更难的事情

  • 不支持 NVFP4（block-16）——如果未来 SVDQuant 风格结果要求 block-16 microscaling 吸收 outlier，Trn3 卡在 block-32。
  • 没有动态 shape——所有张量必须在编译时 shape-resolved。变长 token 的视频模型需要 bucketing。
  • stablehlo.while 约束——diffusion 采样循环完全展开膨胀编译时间；通过 input_output_aliases 做持久化状态可行但对异步候选级 rollout 不友好。
  • CUDA 生态成熟度——xDiT / FastVideo / SVDQuant 每个 kernel 都是手写；Trn3 上要自己写。
  • 成熟的 3D Conv kernel 缺失——NKI Library 只有 Conv1D。

"Trainium-as-research-platform" vs "Trainium-as-product" 论证：把 TrainiumLatent framing 为 research platform 论文——Trn3 是唯一商品云加速器同时有硬件 OCP microscaling matmul + switched all-to-all 144-chip scale-up 域 + Apache-2.0 开源 NKI 编译器。Product 论证（"Trn3 比 H100 便宜"）对 PhD 论文比较弱，引用的也是 Anthropic 数字、reviewer 无法独立验证。Research-platform 论证强是因为 (a) NKI 开源、(b) ISA 显式暴露、(c) Trainium 上完全没有非 Anthropic 的 latent-video 系统工作。

前 Trainium NKI 论文如何处理"为什么不是 GPU"：NeuronMM framing 为"Trainium systolic-array 架构和特殊 data layout 要求的挑战"——即 Trainium 特定的贡献。AccelOpt 显式说 Trainium 是"a widely deployed and representative AI accelerator that exemplifies these challenges"，用 Trainium 作通用 kernel 优化 testbed。ASPLOS 2025 NKI Tutorial / 竞赛强调"bare-metal access"和"self-serve"。TrainiumLatent 应该跟 NeuronMM 的修辞动作走。

  • 停止把 NKI Library 的现有 kernel 当成"已经够好"——每个都用 BF16 写，没用 nc_matmul_mx + quantize_mx + VectorE exponential，这恰好是你的 kernel 要超过它们的地方。

Source ReliabilityCaveats

— 引用与不一致 —
  • HBM 带宽分歧：NKI Trainium3 arch 页写 4.7 TB/s/chip；Trn3 instance 页和 AWS marketing 写 4.9 TB/s。两个都引用，标明来源 URL。你有 Trn3 access——用 micro-benchmark 实测真实带宽（STREAM-like + DMA-only kernel），这本身就是一个有价值的数据点。
  • Trn3 LNC mode 未穷举文档化：第三方报道（SemiAnalysis）说 Day-0 LNC=1 / LNC=2，LNC=8 延期到 2026 年中。Primary AWS doc 只演示 LNC=2。在你的硬件上直接验证 os.environ["NEURON_LOGICAL_NC_CONFIG"] 接受什么值。
  • SBUF/PSUM 间接寻址、Activation2 在 Trn3 arch guide 描述了，但 NKI 0.3.0 仍无 API——不要把计划建在这上面，但要关注 NKI 0.4 release note，可能在论文 submission 前后开放。
  • NeuronLink-v4 per-link 带宽 在 AWS product 页（2 TB/s/chip）有，但 NKI arch doc 没有——同样可以实测验证。
  • Build-on-Trainium credit 仍值得申请：要求开源 + 论文，与你的发表路线一致；AWS credit 可补充硬件 hours。
  • SemiAnalysis 的"128×128 BF16 + 512×128 MXFP8 双 systolic array"说法误导：AWS NKI 主文档澄清是单一物理 128×128 PE array，每 PE 每周期 4 个 MX MAC。论文中引用 AWS NKI 文档原文，不引第三方分析。
  • Anthropic 在 re:Invent 2025 keynote 报的"Trn3 上 90% TensorE 利用率"来自 AIM3335 单一谈话，未独立验证。你的实验有机会成为第一个公开验证（或反驳）这一数字的来源。
  • NxD-Inference 当前视频扩散支持仅限 Flux.1-dev（图像）；把 HunyuanVideo 或 Cosmos 在 Trn3 上 bring up 是 Month-1–2 的主导工作量风险。这个本身可发表（Contribution 5）。
  • Trn3 上 MXFP4 是 OCP block-32（E8M0 scale, E2M1 data）——不支持 NVFP4（block-16）。如果关键贡献依赖 block-16 microscaling，Trn3 给不了；B200/RTX 5090 能。需要在论文里前置说明 OCP MX vs NVFP4 的区别。
