02 / INSIDE THE BLOCK

Residual 就在“⊕ 加回主干”处

点击两种 block 对照。Double block 是串行的两次加法；Single block 是平行两支先汇合，再做一次加法。两者不能用同一段 cache 代码硬套。

Image stream：xℓ
AdaLN(xℓ, timestep) → norm、gA、shift/scale、gM
Joint Attention 与 text 交换信息，得到 Attnimg
x⁺ = xℓ + RA，其中 RA = gA · Attnimg
LN(x⁺) + shift/scale → FFN → FM
xℓ+1 = x⁺ + RM，其中 RM = gM · FM
推荐 cache payload：FM（未乘 gate）
跳步时用预测的 F̂M，仍使用当前 timestep 的新 gM。不要 cache x⁺，否则 fresh Attention 的修正会被覆盖。
Text stream：cℓ
AdaLN(cℓ, timestep) → context norm 与四个 modulation 参数
同一个 Joint Attention 返回 Attntext
c⁺ = cℓ + RA,c
LN(c⁺) + shift/scale → context FFN → FM,c
cℓ+1 = c⁺ + RM,c
Text MLP 也必须单独存
后续 block 的 Attention 会读更新后的 text stream。只缓存 image MLP 而漏掉 text MLP，会改变整条语义路径。
R_A(t) = gate_A(t) · Attention(current x, current c)
R_M(t) = gate_M(t) · FFN(Norm(current x + R_A(t)))
hybrid： x′(t) = x(t) + R_A(t) + gate_M(t) · predict/cache[F_M](t)
重要依赖：Double block 的 MLP 输入依赖刚算出的 Attention 结果。所以我们 cache 的是 MLP 输出支路，不是 MLP 输入，也不是 block hidden state。

为什么这是 Trainium 最好的拆点

源码本来就把两支 RowParallelLinear 的 reduce_output 关掉，在相加后合并成一次 AllReduce。用 m̂local 替换 out_mlp，不增加 collective，也不改 rank 间通信顺序。

这里的“两个 residual”是代数分解

Single block 物理上只有最后一次 residual add；由于 AllReduce 与加法是线性的，可把 Δh 看成 Attention 分量 + MLP 分量，但实现上应保持先合并再 AllReduce。

Anchor step 负责刷新每层 cache；hybrid step 仍经过 57 层，但每层只走 Attention 主计算和轻量 modulation，MLP 支路从设备内状态恢复。

04 / TRAINIUM + AOT

能静态编译，但不能运行时随便分叉

结论来自当前 NXD 结构：固定 shape / TP collective、整段 backbone traced 成 NEFF；项目已有 nn.Parameter + input_output_aliases 的设备持久状态先例。

绿色：架构天然兼容

  • 固定 1024²、B=1、TP=4 编译
  • single block 在 AllReduce 前替换 MLP local partial
  • cache bank 作为 device-resident aliased Parameter
  • 所有 rank 保持同一 collective 拓扑

黄色：需要新实现与测量

  • 新编译 anchor-write / attention-read 两个图
  • 跨 NEFF 的 cache handle 必须验证 zero-copy，且所有输入都留在 Neuron device
  • double block 的 image cache 要匹配 SP sequence shard
  • 两份 history bank 的 HBM 容量、读带宽与 Attention-only 延迟

红色：不要这样做

  • 在 traced forward 里用 Python if / tensor.item()
  • 不同 TP rank 选择不同支路或少做 collective
  • 每步把 GiB 级 cache 拉回 host 再送入设备
  • 把 57 个 block 拆成 57 次 host→NEFF dispatch
Host cadence只做入口选择；不搬 cache tensor

05 / RECOMMENDATION

先验证 single block 拆分，再扩到 57 层

结构正确不等于速度一定划算。新方案不会再获得“整步完全跳过”的极端加速，但它让 prompt / 空间语义通过 Attention 每步重新注入，正对目前油门版本的主要失败模式。

建议的最小实验

  1. 做 1 个 single block 的双图 micro-NEFF：full 与 cached-MLP，确认数值拼接、alias 和单次 AllReduce。
  2. 测真实 block 分解：Attention、MLP、collective、cache read 各自延迟；先决定理论油门上限。
  3. 扩到 38 个 single blocks：用真值 MLP cache 做质量上界，再上 Taylor 预测；避免一开始同时处理 double-stream SP。
  4. 最后扩 double blocks：image payload 按 SP shard 存，text payload replicated；保持所有 rank collective 次序一致。
一句话：它符合 Trainium/AOT，但产品形态应是“两个静态 NEFF + 设备内 alias cache bank”，不是在一个 NEFF 里做动态 if；最值得先落地的切点是 NeuronFluxSingleTransformerBlock.forward() 的 out_mlp。
