DiffCache：用可校准的风险边界换取生成加速

DiffCache 是面向扩散图片和视频生成的可插拔缓存加速系统。这里的“缓存”不是保存最终文件，而是保存生成过程中已经真实计算过的主干网络输出；在后续相近步骤中，系统用历史趋势估计当前输出，从而减少最昂贵的 Transformer 调用。Difflet 是第一个接入它的宿主，而不是系统的永久边界。

离线语义校准回答“多大的便宜误差信号仍然不会造成不可接受的图片损伤”；在线锚点验证只读取便宜信号，动态决定下一段可以连续估计多远。ImageReward 和 VQAScore 永远不进入在线请求路径；任何缓存控制异常都确定性地回到全量真实计算。
当前完整接入：FLUX 文字生成图片模型 目标形态：可接入不同图像和视频生成框架 自动质量合同：已冻结并实机验证 静态与自适应刹车通过；渐进油门独立 holdout 未通过 按请求自动调整：刹车已实现，渐进油门当前关闭 页面背景：固定白色
01 / Reader guide

先说明后文会反复使用的词

本页同时面向系统读者和研究人员。第一次出现的英文名保留在中文解释后面，后文再使用简称。

A. 先理解生成过程

扩散生成

一种逐步生成图片或视频的方法。它从随机数构成的中间状态出发，多次去除噪声，最后解码成可见结果。

用户描述（prompt）

用户输入的文字要求，例如“一只狐狸站在雪地里”。不同描述会产生难度不同的生成轨迹。

中间状态（latent）

生成过程中尚未解码成图片的数值张量。张量可以理解为多维数字数组；每个去噪步骤都会更新它。

去噪步骤（denoising step）

一次“读取当前中间状态、计算模型输出、再更新中间状态”的完整迭代。一张图片通常需要几十次这样的步骤。

主干网络（Transformer）

每个去噪步骤中最昂贵的神经网络计算。缓存加速的主要目标就是减少它被真实执行的次数。

模型输出

Transformer 在当前步骤返回的数值张量，用来描述当前 latent 应该怎样变化；不同模型会把它定义成“噪声”或“速度”。它不是最终图片，而是 Scheduler 推进中间状态所需的输入。

数值更新器（Scheduler）

按照既定数学公式，使用模型输出把当前 latent 更新到下一步。缓存系统不替代 Scheduler，它只提供真实或估计的模型输出。

真实计算（True Compute）

实际运行一次 Transformer 得到当前步骤输出。它成本最高，但可以作为可靠历史和后续验证依据。

估计输出（Estimated Output）

不运行当前步 Transformer，而是根据之前真实输出的变化趋势估计结果。估计输出仍会被 Scheduler 使用，因此误差可能沿轨迹累积。

真实锚点（Anchor Step）

计划中必须执行 True Compute 的步骤。它刷新可靠历史，也让系统能够比较事前估计与实际结果。

开头保护（warmup）

请求开始时连续执行若干个真实步骤，用来建立足够的历史并观察当前请求早期变化。

结尾保护（cooldown）

生成结束前连续执行若干个真实步骤，减少末端误差放大，并保证最终状态得到真实校正。

去噪坐标（index / sigma / timestep）

index 是从第 0 步开始的顺序编号；sigma 表示当前噪声强度；timestep 是 Scheduler 使用的数值坐标。后两者比简单编号更能表达步骤之间的真实数学距离。

语义分界（semantic barrier）

表示前后模型语义或计算阶段发生变化的步骤。跨过分界后，旧历史可能不再可比较，系统必须清理历史并重新真算。

无缓存参考（baseline）

同一请求完全不跳过 Transformer 的生成结果。离线实验用它与缓存结果比较，计算缓存造成的真实质量差异。

缓存配置（Cache Profile）

由成组离线实验得到的“地图、限速和硬护栏”：地图描述便宜误差信号通常怎样随步骤和连续估计长度变化；限速规定信号最多允许到哪里；硬护栏规定 warmup、最大连续估计步数和恢复动作。它不是某个请求的固定步骤表。

B. 再理解缓存系统怎样分工

每请求会话（Request Session）

一次生成请求独有的缓存运行对象。历史、预算、难度和恢复状态都只存在于该会话，请求结束后销毁。

宿主框架（Host Framework）

真正运行模型和 Scheduler 的图像或视频生成系统，例如 Difflet、Diffusers 或 ComfyUI。

适配层（Host Adapter）

把不同宿主框架的请求、步骤坐标和模型输出翻译成缓存核心能够理解的统一格式。

缓存核心（Cache Core）

可插拔的通用子系统，负责步骤安排、输出估计、质量保护、请求状态和记录，但不负责加载模型或解码最终图片。

缓存控制器（Cache Controller）

在线运行时唯一的决策组件。它根据 Profile、当前请求的锚点误差和恢复状态，决定下一段最多连续估计几步。轻微风险直接缩短段长，严重风险进入恢复，反复异常则关闭本请求缓存。

输出估计方法（Cache Method）

只回答“如何根据真实历史算出当前步骤的替代输出”。“外推”是把已经观测到的变化趋势延伸到尚未真实计算的点；一阶外推使用变化速度，二阶外推还考虑趋势弯曲。方法本身不决定何时被调用。

锚点验证（Anchor Validation）

在原本就要真实计算的锚点，先产生一次“假如这一步被估计”的输出，再与真实输出比较。它测到的是局部预测误差，不是最终图片质量；它不增加 Transformer 调用。

恢复与关闭（Recovery / Disable）

控制器的两种安全行为。恢复表示连续真实计算若干步并重建历史；关闭表示本请求余下步骤完全不使用缓存。二者不是独立的聪明系统，而是对连续估计长度施加约束。

统一执行器（Execution Engine）

每一步的最终执行者。它综合步骤安排、质量限制和历史是否就绪，确保最终只发生一个动作：真实计算或使用估计输出。

动态 Plan（实际执行轨迹）

一个请求最终走出的逐步动作序列，例如“真算、真算、估计、估计、真算”。它在请求开始前并不存在，也不是预配置文件；控制器根据实时信号边运行边产生，请求结束后才可序列化用于审计。

运行状态（Runtime State）

当前请求在内存中的状态，包括真实历史、当前连续估计长度、难度尺度和恢复阶段。它不是离线配置，也绝不能跨请求共享。

运行测量（Runtime Measurements）

系统在真实锚点计算估计误差、输出变化和耗时。第一版控制器直接读取同一个锚点误差来调整后续段长；实验开关打开时，Measurement Sink（测量接收端）再把观测副本留在内存、写入文件或发送到监控系统。保存失败不能改变生成决定。

版本化数据文件（artifact）

供程序读取和复现实验的结构化文件。schema 是字段与类型规则；hash 是由文件内容计算出的数字指纹，可用于发现内容是否被改动。

C. 最后理解校准与验证

在线服务与质量合同

在线服务（serving）是系统接收真实用户请求并返回图片或视频的运行环境。这里的“质量合同”不是保证每张图逐像素一致，而是预先声明允许的成对语义下降、目标损伤率和统计置信度，并规定配置不适用或信号异常时回到全真算。

模型与数值身份

revision 是精确模型权重版本；shape 是张量各维长度；dtype 是数字精度类型；量化是用更少位数表示权重或计算。它们可能改变数值结果，因此要被记录。

配置指纹（configuration fingerprint）

将 Scheduler 等关键数值配置规范化后计算出的稳定标识。只有指纹相同，系统才认为两套配置可以共享同一份质量证据。

并行方式（TP / CP）

TP 是张量并行，把同一次模型计算拆到多个设备；CP 是上下文并行，把输入序列拆到多个设备。两者都可能改变数值归约顺序。

离线数据分组

calibration 集用于选择参数和阈值；holdout 集是一套事前冻结、与前面所有选参样本完全不同的最终考题。开始 holdout 后不能再根据结果修改候选或阈值，否则它就不再是独立检验。两组不能包含相同 prompt。

图片差异指标（PSNR / LPIPS）

PSNR 比较两张图片对应像素，数值越高越接近；LPIPS 比较深度特征所表达的感知差异，数值越低越接近。它们适合描述“同不像”，但不同不一定表示 prompt 语义受损，因此不再单独承担 serving 验收。

语义与偏好评分

VQAScore 检查图片是否表达了 prompt 要求的对象和关系；ImageReward 更接近人类对内容匹配、自然程度和整体观感的综合偏好。二者只在离线对缓存图与无缓存图做成对评分，绝不在线运行。

成对损失与自动允许范围

成对损失等于“无缓存分数减去缓存分数”，正值表示缓存图得分下降。允许范围（equivalence margin）表示评分下降最多可以到哪里。当前实验不使用人工标签：先让同一个 prompt 在完全不缓存时用三个不同随机 seed 正常生成，再把这些正常图片之间的分数波动作为尺度；候选图片不能参与确定这条线。

自动失败率与置信上界

任一语义指标的成对下降超过自己的允许范围，就记为一次“自动指标失败”。样本有限时还要报告统计上仍可能达到的最高失败比例，称为置信上界。这个结果只说明冻结评分器下的非劣性，不等同于人眼质量保证。Profile 只有在独立 holdout 上满足预设上界才可发布。

排序相关（Spearman ρ）

衡量两个量是否大致同升同降，范围为 −1 到 1。这里用它检查“在线风险信号越大，最终质量损失是否通常也越大”。

解释程度（R²）

衡量一个简单模型能解释多少观测变化。越接近 1，表示“一个请求难度系数”越能解释锚点误差；接近或低于 0 则说明这种简化不可靠。

指数平滑（EWMA）

一种让近期观测权重更高、但仍保留部分历史的移动平均。它减少单个异常点造成的抖动，系数决定系统反应快慢。

归一化（normalization）

把原始信号除以参考尺度，转换成可跨步骤或请求比较的比例。例如锚点估计误差为 0.02、离线预期为 0.01，归一化结果就是 2，表示风险约为预期的两倍。

状态机（state machine）

把系统限制在少数几个有名字的阶段，并明确哪些事件允许从一个阶段转到另一个阶段。它让恢复行为可预测、可测试，而不是由零散条件随意跳转。

02 / Core idea

缓存到底省掉了什么

一次扩散生成包含多次去噪。通常每一步都调用 Transformer；缓存系统尝试在部分步骤中估计 Transformer 的输出。

当前 latent

生成过程此刻的中间状态。

做出选择

这一步真实计算，还是允许使用估计输出。

得到模型输出

真算 Transformer，或从历史结果估计。

Scheduler 更新

使用该输出推进到下一步 latent。

继续检查

到达真算锚点后重新评估风险。

论文和产品的身份仍然是加速系统：

DiffCache 的主要结果仍然是给定质量边界下的生成加速比。离线语义校准和在线安全回退不是另一个独立监控产品，而是让系统能够选择更激进、仍可审计的缓存强度。质量测得更准确，可能释放原先被像素门误杀的 2× 左右候选；但正式质量合同只能在阈值预注册和足量独立 holdout 之后声明。

真算

运行 Transformer

结果最可信，但也是主要耗时来源。真算结果会成为后续输出估计的历史依据。

估计

估计当前步输出

不是猜测最终图片，也不一定原样复制上一份模型输出；泰勒趋势外推（Taylor extrapolation）会用最近几个真实输出估计变化速度或弯曲程度，再把趋势延伸到当前步骤。

锚点

用于校正的真算步骤

锚点重新获得真实输出、刷新历史，并为在线风险判断提供证据。

一阶估计 ≈ 上一次真算输出 + 历史变化速度 × 当前步距离

单步估计

真估真估真

每次只连续跳过一步，下一步立即真算校正。更稳，但节省较少。

连续估计

真估估估真

一次真算后连续跳过多步。加速更高，但 latent 已被前面的估计影响，误差可能逐步累积。

03 / Runtime layers

三个核心对象完成在线缓存

在线请求路径必须小而明确：会话隔离请求，控制器只决定连续估计长度，输出估计方法只计算替代输出。最终动作始终只有真实计算或使用估计两种。

01 / Cache Session

隔离并执行一个请求

保存真实历史和本请求状态，把控制决定变成唯一动作，并把真实或估计输出交回宿主。当前静态缓存已经使用每请求会话，任何状态都不得跨请求复用。

02 / Cache Controller

决定下一段有多长

读取 Profile、锚点误差和恢复状态，输出下一段连续估计长度 L。轻微风险缩短 L；恢复期间令 L=0；本请求关闭缓存后永久令 L=0。它不运行模型，也不计算最终图片分数。

03 / Output Predictor

怎样得到替代输出

使用真实锚点历史外推当前 Transformer 输出。第一版使用 TaylorSeer；估计结果不会被当成新的真实历史，避免错误自我强化。预测器不决定自己何时被调用。

控制逻辑可以用两行概括：

锚点之后，控制器把 L 限制在 Profile 的最小间隔与硬上限之间；连续低误差时只增加 1，高误差时缩短，恢复期或关闭缓存时令 L=0。warmup、轻微收紧、恢复真算和关闭缓存都通过同一个 COMPUTE/PREDICT 执行路径完成，Runner 没有为每种情形增加独立模型调用分支。

四种数据的职责不能混淆

文件格式可以使用独立的格式名称和整数修订号，但代码中的类名和函数名不携带 V1、V2 等代际后缀。旧格式只承担实验复现，不决定新运行时的命名。

04 / Pluggable subsystem

通用缓存核心只负责缓存控制，宿主继续拥有生成流程

目标不是把 Difflet 的完整生成流程搬进新代码库，而是抽出一个请求级缓存核心，使它可以嵌入 Difflet、Diffusers、ComfyUI 或其他在线扩散生成系统。

缓存核心（Cache Core）负责

匹配 Cache Profile、创建每请求会话、决定连续估计长度、估计输出、执行恢复约束、维护真实历史，并产生运行记录。

它只交付当前步骤应该使用的模型输出，不接管完整生成流程。

宿主适配层（Host Adapter）负责

加载模型、把用户文字转换成模型输入、调用真实 Transformer、使用 Scheduler 更新 latent、管理批处理（batch，即一次并行处理多个请求）、设备通信与计时，并把最终 latent 解码成图片或视频。

宿主始终保留完全不使用缓存的原始路径。

最重要的边界：

缓存核心不依赖 Difflet 的命令行入口、FLUX 的完整生成流程、AWS Trainium 机器学习加速器及其 Neuron 编译与运行软件，也不直接读取某个在线服务的私有请求对象。适配层把这些宿主信息翻译成稳定协议；核心只读取统一的请求描述、去噪坐标、模型输出和“历史已经失效”等语义事件。

主数据流从上到下

宿主发起请求，适配层统一信息，缓存核心提供当前步模型输出，最后仍由宿主 Scheduler 更新 latent。最终图片或视频从不进入缓存核心。

在线决定只有一个数字

控制器只决定下一段连续估计长度 L。warmup、预算、最大连跳、轻微收紧、恢复和关闭都是 L 的约束来源，不形成六套执行路径。

慢模型被隔离在离线侧

ImageReward 和 VQAScore 只参与 Profile 的阈值标定，在线代码不导入它们的包、不读取最终图片。运行测量接收端只拿观测副本，保存失败也不能修改生成决定。

一次请求如何穿过插件边界

宿主开始请求

提供模型身份、张量形状、步数、Scheduler 配置指纹和只属于本请求的标识。

核心创建会话

匹配 Cache Profile；不匹配时创建“全部真实计算”的会话，而不是让请求失败。

每一步询问决定

宿主传入步骤序号、噪声坐标和历史失效事件；核心返回“真实计算”或“使用估计”。

宿主推进生成

真实或估计输出都交回宿主，由宿主调用 Scheduler 更新 latent。

结束并记录

核心清理请求状态并输出可选运行记录；宿主负责最终结果和服务统计。

session = cache_core.start_request(request_info, schedule, profile)

for step in schedule:
    decision = session.before_step(step.context)
    if decision.should_compute:
        output = host.compute_transformer(step)
        session.record_anchor(step.context, output)
    else:
        output = session.estimate(step.context)

    latent = host.scheduler_step(output, latent)

dynamic_plan, measurements = session.end_request()

上面的伪代码只表达调用顺序，不要求宿主使用相同类名。接口故意不接收最终图片，也不调用 Scheduler。缓存核心的可移植边界是“当前去噪步骤的 Transformer 输出”，而不是完整的文字生成图片或文字生成视频流程。

Host Adapter

第一版明确不泛化的内容：

缓存核心第一版只替代一次完整 Transformer 调用的最终输出。更细粒度的方案——例如缓存输入序列单元（token）、注意力关系计算（attention）、某一网络层或计算块的中间特征，以及残差张量——都必须进入模型内部。它们需要另一套“模型内部适配层”和“缓存目标”协议，不应塞进当前步骤上下文，否则通用接口会失去清晰边界。

Trainium 专项优化放在通用核心下面

控制算法保持硬件无关，但张量怎样存放和小运算怎样执行可以针对 AWS Trainium 优化。当前 TaylorSeer 历史已经保持为设备张量；下一步先把少量真实历史做成固定形状的 HBM（设备高带宽内存）环形缓冲，避免每步动态分配和主机往返。TP 多设备只汇总误差平方和等标量，不传输完整历史张量。

先测，不急着融合

分别测量 Transformer、TaylorSeer、锚点误差、Scheduler 和跨 TP 汇总。只有小运算成为可见瓶颈，才考虑把 predictor、误差汇总或 Scheduler 编成更大的固定图。

HBM 保存跨步骤历史

NeuronCore 片上 SRAM 容量小、生命周期短，适合单个编译图内部复用，不适合把大输出跨几十个步骤长期保存。跨步骤历史应留在 HBM，并保持固定 shape 和分片方式。

质量信号不因融合消失

即使未来把小张量运算融合进 Neuron 图，也只输出控制器需要的少量标量和估计输出。实验需要详细记录时再通过可选接收端保存，不把完整历史搬回 CPU。

先在 Difflet 内验证，再按已经通过测试的边界拆库

当前不为追求目录美观立即创建外部仓库。difflet/pipeline/cache 已通过 AST 导入边界测试，禁止依赖 Difflet serving、common、具体模型、ImageReward、VQAScore 或其大型模型依赖。渐进油门独立复检已完成但未通过；待保守 Profile 和 loader 落地后，再按已经被测试证明的依赖边界抽成独立 Python 库。

05 / Offline profile

地图来自便宜信号，限速来自语义碰撞测试

在线只能看到锚点误差等便宜信号，不能知道“如果完全不缓存，最终图片本来会是什么”。离线实验愿意为同一请求跑两次完整生成，因此负责把便宜信号换算成可发布的安全边界。

地图：哪里容易出现估计误差

地图全部使用在线能够便宜测量的单位。它描述：当前处于去噪早期、中期还是晚期，离上一个真实锚点已经连续估计几步，以及在这种位置上锚点误差通常有多大。候选表示可以用一张 error_surface(method, gap, sigma) 曲面表达这些规律；能否简化成这张曲面仍需实验证明。

限速：便宜信号最多允许到哪里

限速 ε 不是由误差曲线自己产生。离线先自动确定语义评分允许下降多少，再把缓存图与同 prompt、同 seed 的无缓存图比较，找出在预设失败率上限内仍可使用的最大 ε。在线只读取这个数字，不运行任何图片评分模型。

成对生成

同 prompt、同 seed 分别运行无缓存和缓存候选。

冻结允许范围

只用无缓存图片在不同 seed 下的正常 VQAScore 与 ImageReward 波动确定两条线；缓存候选不参与。

自动标记越界

缓存图与同 seed 无缓存图配对；任一指标下降超过自己的线，就记为失败。

关联便宜信号

检查锚点误差、连续估计长度和阶段位置能否区分无害与损伤。

搜索最大 ε

逐步增加限速，统计每一档的加速比和两类损伤率置信上界。

独立复检

冻结全部参数后再打开从未用于选参的 holdout；不能看完结果再改线，通过后才发布。

两个语义分数不混成一个魔法总分

VQA 损失 = VQAScore(baseline) − VQAScore(cache)
偏好损失 = ImageReward(baseline) − ImageReward(cache)

两种损失分别与各自预先规定的允许范围比较。对于每个候选 ε，离线实验分别计算“VQA 损失越界率”和“偏好损失越界率”；两个置信上界都不超过目标时才接受。最终发布的在线限速取两类约束中更保守的结果，不通过加权平均掩盖任何一类失败。

为什么语义评分绝不能放进在线请求

它们太慢、太重

ImageReward 和 VQAScore 自身就是大型视觉或视觉语言模型。为每张生成图再运行它们，会吃掉缓存节省的时间，还要求在线部署另一套权重和编译产物。

得到结果时已经太晚

两个评分都需要最终图片。等分数出现时，全部去噪步骤和缓存决定已经结束；它们无法修正本次请求，只能要求昂贵的重新生成。

线上没有成对参考

真正有意义的是“缓存图减无缓存图”的配对差值。在线若再完整生成一张无缓存参考，成本恰好抵消缓存收益。因此线上只能使用被离线语义实验校准过的便宜风险信号。

语义分数不能直接代入公式得到 ε：

VQAScore 和 ImageReward 的单位不同，也都不是天然校准好的“损伤概率”。第一步先用正常无缓存生成的 seed 间波动，分别得到两种指标自己的允许范围；第二步让控制器在多个 ε 下离线运行，形成“ε、加速比、VQA 越界率、偏好越界率”表；最后选择满足目标的最大 ε。Calibration 集负责选择，完全独立的 holdout 只负责最终确认。

不同质量指标承担不同工作

工作主要指标怎样使用
代码数值回归latent cosine、冻结轨迹与逐位一致性检查代码修改是否意外改变算法；应保持严格，不作为用户能否接受图片的唯一判断
研究诊断PSNR、LPIPS、SSIM、逐步 latent 差异分析误差从哪里出现、怎样积累，以及不同论文口径；不把“不同”自动等同于“损坏”
离线 serving 验收VQAScore 与 ImageReward 的成对损失、自动失败率及其置信上界标定 Profile 限速并验证最终动态控制器；这些慢指标不进入在线运行时，也不声称等价于人眼判断

Profile 与 Plan 的最终定义

Profile 是请求开始前存在的公共规则

它保存地图、限速、最大连续估计长度、最少 warmup、恢复长度和适用范围。同一 Profile 可以服务大量新 prompt，但只在请求身份落入已验证范围时启用。

Plan 是请求运行后形成的实际轨迹

它是每一步 COMPUTE/PREDICT 的真实序列。两个新 prompt 即使使用同一 Profile，也可能因为锚点误差不同而走出不同 Plan。它不是 serving 前遍历并保存的路书。

当前发布候选：L 从 8 开始，只能缩短到最小间隔；严重超线时 L = 0
实验代码也支持“连续稳定后 L 增加 1”，但发布配置明确关闭这个开关

第一版没有直接实现“逐步误差相加”的复杂账本，因为现有证据没有证明逐步成本可加。当前实现采用更小的机制：以静态 w6/i8 为起点，风险升高时收紧、恢复或关闭缓存。实验代码能够在连续低误差锚点后逐级增加间隔，也能把加速推迟到去噪后段；但两组独立实验仍发现自动失败，因此发布候选禁止主动增加间隔。未来只有在新的提前信号或新的估计方法通过全新 holdout 后，才会打开该能力。

自动损伤样本支持刹车，但不足以批准油门：

边界数据共形成 112 组成对样本，其中 7 组超过冻结后的 ImageReward 或 VQAScore 允许范围。主要锚点误差信号在“同一候选内部”得到宏平均 AUC 0.775，超过预先规定的 0.75；这说明它总体上能排序风险，足以在数值异常时减少缓存。后续八 seed 审计却发现，唯一自动失败 seed 的最大锚点误差是八个 seed 中最低的，因此这个总体相关性不能变成逐请求保证，也不能批准主动增加缓存强度。这里的 AUC 表示随机抽取一个失败样本和一个通过样本时，信号把失败样本排得更危险的概率；它不表示每一个失败都会被发现。

Cache Profile 只保存运行时真正需要的内容

组保存内容边界
适用范围模型族和允许的精确权重版本、Scheduler 配置指纹、任务形状与步数范围、数字精度和估计方法范围不匹配时，本请求从第一步起完全真实计算
便宜信号地图按去噪阶段、连续估计长度和方法组织的误差参考；必要时包含 warmup 参考只有实验证明可迁移的维度才进入 Profile
限速与硬护栏经语义损伤率标定的 ε、最大连续估计长度 K、最少 warmup/cooldown 和最后一步真算规则在线只能收紧，不能突破离线验证边界
三状态参数严重超阈线、恢复真算步数、稳定计数和多少次异常后关闭本请求缓存只驱动 ACTIVE、RECOVERY、DISABLED，不允许状态无限增长
审计证据校准集和 holdout 内容指纹、语义允许范围、损伤率目标与置信度、代码和依赖版本缺失、未知或不兼容字段时拒绝启用缓存，但不让生成请求失败

性能记录与质量 Profile 分开保存。硬件、编译器和 TP/CP 并行方式只有在成对实验表明数值路径等价时才共享质量证据；否则使用独立 Profile 或直接全真算。这样避免为每个性能组合复制整套语义配置，也不把未经证明的环境视为等价。

离线校准不是每个组合都重跑一次

新模型族：一次完整校准

第一次接入结构明显不同的模型时，才运行少量 baseline、两三个风险档和独立 holdout。FLUX 当前的大量实验同时承担了发现指标、控制信号和搜索范围的研究工作，不能当成以后每个模型的固定成本。

相近变更：8–16 个哨兵样本

同一模型的小 revision、编译器、分辨率或并行方式变化，先比较数值路径和少量代表性请求。结果等价则沿用原 Profile；只有超出已验证范围才重新做完整校准。

线上请求：零语义评分

每个新 prompt 只读取一个很小的 Profile 文件并执行锚点测量。不会运行 ImageReward、VQAScore，也不会为该请求事先生成 baseline。

06 / Per-request loop

在线司机只看仪表盘和限速牌

在线控制器不训练模型、不查看最终图片，也不运行 VQAScore 或 ImageReward。它只读取 Profile、锚点误差和少量计数，决定下一段连续估计长度 L。

匹配 Profile

请求信息落在验证范围且配置指纹一致时才启用；否则整个请求全真算。

开头连续真算

建立可靠历史，并用参考曲线计算初始难度 d₀。

规划连续估计段

逐步累加预计误差成本；达到 ε 或 K 前安排下一个锚点。

锚点对照测量

锚点真算前先估计“如果这一步改用缓存会得到什么”，再与真实输出比较。

更新段长

轻微风险直接缩短下一段；严重风险进入恢复并令 L=0；反复异常则关闭本请求缓存。

锚点对照估计：利用计划内真算步骤检查缓存误差

“对照估计”表示这个结果只用于和真实输出比较，不会被 Scheduler 使用，也不会改变最终生成轨迹。因为锚点本来就必须真实计算，所以这项测量不会额外增加 Transformer 调用，只增加少量张量加减和误差汇总。

锚点真算前

先得到“假如跳过”结果

在历史已经就绪时，使用当前 Cache Method 和旧的真实历史估计该锚点输出。只做张量外推，不运行 Transformer。

同一个锚点

再执行真实 Transformer

真实输出仍然用于 Scheduler 和历史更新；对照估计只用于计算误差，不进入生成轨迹。

局部误差

形成请求相关证据

e = ‖shadow − actual‖ / max(‖actual‖, tiny)。双竖线表示把整个张量的差异汇总成一个非负长度；分母用真实输出长度消除整体数值尺度影响；tiny 是防止真实输出恰好为零时除零的极小正数。汇总方式和计算精度必须写入运行记录协议。

候选更新：difficulty ← clamp(EWMA(e ÷ expected_error(method, gap, σ_anchor)))

这条候选更新先计算“本次实际锚点误差 ÷ 地图中同位置的预期误差”。比例大于 1 表示当前请求在此处比离线典型样本更难估计。EWMA 是近期观测权重更高的平滑平均；clamp 表示把结果限制在实验验证过的范围。该更新尚未进入生产控制，只有对语义损伤具备稳定预测能力后才允许实现。

执行决定保持最小：

控制器可以返回段长和原因用于审计，但会话对每个步骤最终只执行 COMPUTE 或 PREDICT。轻微收紧不是状态，只是下一段 L 更小；恢复不是第三种模型调用，而是连续若干步选择 COMPUTE。

可以免费记录多个信号，但第一版只允许一个主信号控制

锚点估计误差

衡量当前 latent 附近是否容易被历史趋势估计，是待验证的第一主信号，但不是真实最终质量答案。

真算输出变化

比较相邻真实锚点输出变化了多少，以及变化速度本身是否在加快、减慢或转向；后一个量称为曲率。

Latent 更新幅度

Scheduler 接受输出后，中间状态实际移动了多少。

数值有效性

检查历史是否就绪、坐标是否唯一、张量形状是否符合约定，以及结果是否没有 NaN（无法解释的非数值结果）或无穷大。

不可观测边界：

一条缓存轨迹可能已经偏离无缓存参考轨迹，却仍然在当前位置表现平滑。在线服务只有当前这一条轨迹，没有第二张无缓存图片，因此无法计算成对语义损失。所有在线信号都只是风险代理，必须先在同时包含“确认无害”和“确认损伤”样本的离线数据中验证，再由最大连续估计步数 K、限速 ε 和异常时回到全真算共同兜底。

当前主信号已经通过自动损伤排序门：

旧分析把锚点误差与像素或 latent 相似度关联，结论不稳定。改用冻结后的 ImageReward/VQAScore 自动损伤标签，并在同一候选内部去除缓存强度混淆后，主要信号的宏平均 AUC 为 0.775，超过预注册的 0.75。因此同一套控制器现在允许“高误差踩刹车、连续低误差逐级踩油门”；最大间隔和阈值仍必须由离线 calibration 与独立 holdout 约束。

07 / Recovery and fallback

状态机简单，安全动作确定

状态只在系统行为模式真正不同时存在。轻微风险通过缩短段长处理，不单独创建状态；恢复期的稳定观察只是计数，也不创建状态。

ACTIVE → 严重超阈 → RECOVERY → 稳定后 → ACTIVE ；反复异常 → DISABLED
状态名普通语言含义允许的下一步
ACTIVE
缓存可用		按 Profile、当前难度和硬上限安排连续估计段；轻微风险只把下一段 L 缩短稳定时继续；严重超阈时进入恢复
RECOVERY
恢复真算		令 L=0，连续执行 Profile 指定数量的真实步骤，丢弃受怀疑历史并重建可靠历史；稳定观察由内部计数完成稳定后回到 ACTIVE；再次异常则延长恢复或关闭
DISABLED
本请求已关闭缓存		触发次数达到离线配置中的关闭上限，余下步骤全部真实计算单向状态，本请求内不重新开启缓存
情形确定性动作是否失败请求
Cache Profile 不匹配、模型权重版本未验证或 Scheduler 指纹不符从请求开始就不启用缓存否，使用完全真实计算的原始路径
Warmup 或恢复后，真实历史暂时不足继续真算直到历史重新就绪否，也不永久关闭缓存
历史就绪后信号缺失、出现 NaN（不是有效数值的计算结果）、重复坐标或其他缓存层错误关闭本请求缓存，清理缓存状态否，后续全真算
底层模型错误、OOM（设备内存不足）、设备故障或 Scheduler 本身失败把原始错误继续交给上层处理，缓存层不得伪装成可恢复是，因为这不是缓存控制故障
异常时回到原始路径

也称 fail-safe to baseline：缓存控制失败时仍运行完全真实计算，不把“请求能否成功”建立在缓存必须正常之上。

只捕获缓存异常

禁止使用不区分错误类型的 except:；模型、内存和设备错误必须原样向上传递。

逐请求隔离

状态、预算、历史和永久关闭标记都属于单个请求，不影响其他请求。

恢复专题页将在实现三状态控制器时同步更新：《缓存质量恢复架构》。轻微收紧继续用段长变化表达，恢复期观察继续用计数表达，不再增加额外状态。

四个问题的当前答案

“预注册”表示先写下测量方法、通过门槛和失败后的替代方案，再运行正式实验。已经回答的问题不再重复增加新的门。

问题怎样验证通过后失败分支
自动失败标签是否稳定评分模型权重固定；允许范围只从无缓存 seed 波动产生已通过；合同工具与模型身份已经冻结评分模型发生变化时重新标定，不静默沿用
便宜信号能否预警112 个边界样本、7 个自动损伤；另对一个失败 prompt 做八个 seed 的同候选审计宏平均 AUC 0.775 支持把它用于保守刹车；但失败 seed 的最大锚点误差反而是 8/8 最低，不能据此踩油门或承诺逐请求安全只允许减少缓存强度；增加缓存强度必须等待新的、能提前识别失败的信号
一个难度数和加法账本是否够现有证据尚未证明逐步误差可加暂不引入账本；使用更直接的锚点阈值和逐级段长保持简单实现，不为满足设计图而增加未验证模型
风险限值是否带来可发布前沿固定 TaylorSeer、warmup 和坐标，先检验 K 与阈值，再单独检验“去噪后段才增加间隔”K=12 原候选 2/32；阶段门候选在另一组为 1/32。阶段门提高了速度，但没有消除尾部失败不发布渐进油门，不在已经开封的失败请求上继续调参
候选数量不能冒充独立样本数量：

同一批 prompt 跑六个候选会产生很多图片，但每个候选仍只有 16 个 calibration 样本。正式 32-prompt holdout 要求 0/32 失败，才能把 95% 单侧失败率上界压到 8.94%。不同候选共享的 baseline 不会被重复计算成新的独立证据。

Calibration 通过不等于 Profile 可以发布：

两轮 calibration 没有发现损伤，但第一组全新 holdout 找到两例越界；阶段门又在另一组独立请求中找到一例 VQAScore 越界。这正是独立复检存在的原因。已开封结果只能用于否决或诊断，不能被当成 calibration 数据反复挑选参数；任何新候选都必须重新冻结并接受另一套未开封 holdout。

本阶段退出条件

自动允许范围、边界重判、静态与刹车版检验均已完成。阶段门与八 seed 信号审计进一步证明：当前锚点误差可以保守地踩刹车，却不能可靠识别所有语义失败，也没有资格主动增加缓存强度。本阶段以“保留刹车版、拒绝渐进油门”结束；小型 Cache Profile loader 不承载阶段油门候选。

已完成：自动质量合同

允许范围、损伤组合规则、统计置信度、模型权重和实验身份均已冻结；旧 PSNR/LPIPS/latent 门保留为诊断和数值回归。

w6/i8 与只会收紧的控制器先同场通过正式 32-prompt 检验；第二组独立冻结审计中刹车版为 1/32，累计 1/64 的 95% 单侧上界为 7.20%。自适应路径确实在风险请求上增加真算，没有永久关闭或请求失败。

随后：干净测速、Trainium 内存优化和扩模型

关闭实验记录重测 serving 延迟；把历史张量改为固定形状的设备内环形缓冲，测量 predictor、Scheduler 和跨 TP 通信后再决定是否融合小图。新模型族使用窄 calibration；相近 revision 只做 8–16 个哨兵样本。
