01

Why nowContext

Difflet has shipped the M0–M3 arc: DiffletPipeline + compile cache, Flux end-to-end, Wan 2.2 spike + numerical alignment, and HunyuanVideo v0 (hybrid pipeline, TP=4, 4-step trajectory cosine ≥ 0.9999 vs HF). M4 (Qwen-Image, LTX-2, Z-Image) is still "Planned" per README.md:21 — Qwen-Image has a registry stub at difflet/registry.py:228-245 pointing at an as-yet-uncreated difflet/models/qwen_image/entry.py, no model code, and no scripts/qwen_*.

The next high-leverage research direction is a candidate-aware latent runtime: 4 hardware-coupled mechanisms — latent prefix cache, cross-candidate KV sharing, early-exit rollout, stage-adaptive MX scheduling — that all need a new candidate axis N and several new ops the tree doesn't yet have.

— Decision baked in by the user (no further input needed before implementation) —
  • Direction: the 4 Paper A mechanisms above.
  • Breadth: open all 4 as an M5.x backlog (analogous to the existing m3-hunyuan/31-M3-x-backlog convention).
  • Framing: capability first — milestone cclog entries get sized but not started; publication framing deferred.
  • v0 candidate workload: HunyuanVideo at 320x512x61 only. Qwen-Image is NOT an option until M4 lands.

Intended outcome of this plan: three local-only markdown files under cclogs/m5-latent/ that an implementer can pick up cold to start any of M5.0–M5.4 without re-deriving scope. No code change.

05

Next concrete sessionM5.0 — Pre-flight

Three preconditions, packed as one milestone. Closure criterion: a single HunyuanVideo Trainium artifact runs N=4 candidates of one denoise step without recompile, and the orchestrator emits a per-step trajectory metrics JSON in the existing scripts/hunyuan_vae_parity.py:77-78 shape ({cosine, max_abs, mean_abs, ...} per step).

1 · Candidate-axis config

Add an N candidate dimension to the parallel config surface.

  • Target file: difflet/pipeline/parallel_config.py (currently 33 lines, DiffletParallelConfig frozen dataclass with tp_degree, cp_enabled, cfg_parallel_enabled).
  • Change: extend DiffletParallelConfig with num_candidates: int = 1. The dataclass is frozen=True so cache keys remain stable; bump MANIFEST_SCHEMA_VERSION in difflet/pipeline/compile_cache.py:34 from 3 to 4 because the cache hash inputs change (it is folded through DiffletParallelConfig.to_cache_dict() at line 31).
  • world_size math: the candidate axis does NOT consume cores — it shares the existing TP/CP world via batch tiling. Leave the world_size property at lines 26-29 unchanged. Validation hook in __post_init__ enforces num_candidates >= 1.
  • Wiring: pass through DiffletPipeline.from_pretrained at difflet/pipeline/difflet_pipeline.py:49 (parallel kwarg already exists). Default num_candidates=1 so all four registry entries (difflet/registry.py:180,199,220,240) continue to validate unchanged.

2 · Decode-free latent trajectory metric harness

Do NOT extend difflet/utils/benchmark.py. That file is a verbatim NxDI fork (banner at lines 1-7, references GenerationConfig, sampling_params, NUM_IMAGE_PER_PROMPT) for LLM token-generation benchmarking. Its LatencyCollector class at lines 490-499 is the only generic piece — it's 12 lines of pre_hook / hook time bookkeeping.

Instead create:

  • New file: difflet/utils/latent_trajectory.py — small (one class + one writer fn) for diffusion-side per-step metrics. Reuses the LatencyCollector pattern (pre_hook / hook) but operates on torch.Tensor snapshots, not just timestamps. Computes {step, latency_ms, latent_cosine_vs_ref, latent_mean, latent_std}. Writes a JSON list with the same json.dumps(stats, indent=2) shape as scripts/hunyuan_vae_parity.py:182.
  • Hook site: HunyuanVideoOrchestrator._denoise at difflet/models/hunyuan_video/pipeline.py:142-170 already has a return_trajectory path (lines 90-92, 168-169) that materialises latents.detach().cpu() per step. Wrap that path through the new collector. The orchestrator already takes return_trajectory: bool (line 74) — add metrics_out_path: Path | None = None peer parameter.
  • Reference latent for cosine: cached N=1 run with the same seed. Persist under the existing compile-cache directory layout (difflet/pipeline/compile_cache.py:_default_cache_dir).

No Neuron Profiler 2.0 yet. That is M5.D2.

3 · Run N=4 HunyuanVideo end-to-end

  • Workload: HunyuanVideo at the default registered shape {height: 320, width: 512, num_frames: 61} (difflet/registry.py:221), TP=4.
  • Synthetic scorer: "keep all" — every candidate survives every step. Sufficient to validate the candidate axis plumbing without needing M5.3 exit logic.
  • Driver: small new script scripts/hunyuan_candidate_smoke.py modelled on scripts/hunyuan_hybrid_orchestrator_smoke.py (the existing M3 orchestrator smoke). Asserts: no recompile between N=1 and N=4; per-step metrics JSON written; trajectory cosine of N=4 seed-0 matches the N=1 reference within 1e-6.

Eyeball cost: ~1 week

5.1
Cross-candidate state sharing · Mechanism 1

Latent Prefix Cache

Foundational
What

Paged latent cache: replicated HBM v0, shared prefix + per-candidate divergence blocks. Fork-on-divergence detection via L2 distance with threshold τ. vLLM PagedAttention analog for video DiT.

Why

Most candidates share the first ~30 % of denoise steps; recomputing them per-N is pure waste. Foundational — M5.2 and M5.3 both reuse τ.

Trigger

As soon as M5.0 lands and N≥2 runs measure ≥ 20 % HBM duplication on early steps. The trajectory JSON from M5.0 is the evidence source.

Files
  • New difflet/pipeline/latent_cache.py (paged store + fork detection).
  • Integration hooks in each model orchestrator (difflet/models/hunyuan_video/pipeline.py:_denoise at line 142; difflet/models/wan/pipeline.py:WanOrchestrator; difflet/models/flux/pipeline.py:NeuronFluxPipeline — Flux extends diffusers.FluxPipeline, so the hook goes in the overridden __call__ at line 65).
  • State aliasing seam: every Trainium backbone currently passes input_output_aliases={} (verified at difflet/backends/trainium/hunyuan_video/backbone.py:140, difflet/backends/trainium/wan/backbone.py:129, difflet/backends/trainium/wan/vae.py:134, difflet/backends/trainium/wan/text_encoder.py:116). The LLM KV cache pattern at difflet/backends/trainium/core/model_wrapper.py:1590-1638 is the worked reference — same input_output_aliases mechanism, different state shape (latent block instead of past_key_values).
Rough cost

3–5 working days for HBM-only v0; +1 week for SBUF-tier prefix if v0 evidence justifies

5.2
Compute sharing across candidates · Mechanism 4

Cross-Candidate KV Sharing

Tightly Coupled
What

MQA-style sharing of K/V projections across candidates before fork. Q stays per-candidate; K, V are computed once and broadcast.

Why

Drops 3N projection matmuls to 2 + N in the pre-fork window. Tightly coupled to M5.1: the same τ that triggers prefix-cache fork triggers per-candidate K, V.

Trigger

After M5.1 lands. Standalone has no benefit.

Files
  • difflet/ops/attention.py — add a candidate-shared K/V variant.
  • Per-model attention layers (difflet/models/hunyuan_video/modeling_hunyuan_video.py, difflet/models/wan/modeling_wan.py).
  • difflet/backends/trainium/ops_impl/attention.py:9 already routes through nkilib.core.attention.attention_cte (attention_cte at line 12); keep that for the per-candidate Q × shared K matmul.
Rough cost

2–3 working days once M5.1 exists

5.3
Per-candidate adaptive compute · Mechanism 2

Early-Exit Latent Rollout

Async Dispatch
What

Per-candidate value-head decides exit; cross-core rebalance for surviving candidates.

Why

Candidates that will not be selected should not pay full denoise cost. GPU-blocked by NCCL synchronisation cost.

Trigger

After M5.1 (release HBM blocks on exit). For v0, prove the rebalance path with a synthetic oracle exit (e.g., random or threshold-on-step-index) on HunyuanVideo — no learned exit head needed to validate the plumbing.

Files
  • New difflet/pipeline/scheduler.py — host-side rebalance loop.
  • Orchestrator changes mirroring M5.1.
  • New shared exit-head module under difflet/layers/.
  • nki.collectives.all_to_all_v first integration — current difflet/backends/trainium/ops_impl/collectives.py exposes only TP gather_tp_dim, reduce_tp, scatter_tp_dim (lines 20-42). Add all_to_all_v here next to those.
Rough cost

4–6 working days for plumbing + synthetic exit; learned exit head is a follow-up of its own

5.4
Runtime-adaptive precision · Mechanism 3

Stage-Adaptive MX Scheduling

Blocks on M5.D1
What

Runtime calibration probe per (stage, layer) picks MXFP4 / MXFP8 / BF16; decisions cached and shared across candidates.

Why

Static quantization is per-model hand-tuned; runtime adaptive is portable. Trn3 MX group=32 aligns with DiT head_dim ∈ {64, 128}.

Trigger

Blocks on M5.D1 (MX op surface). For motivating data, use HunyuanVideo's bf16-vs-fp32 step-cosine deltas observed in M3 (per the 4-step trajectory min cosine 0.9999 reported in README.md:18) — if any per-step cosine dips below a chosen gate, that layer is a candidate for higher precision. Do not cite Qwen-Image data — M4 isn't ported.

Files
  • New difflet/ops/mx.py exposing nc_matmul_mx, quantize_mx via the existing dispatch pattern (difflet/ops/_dispatch.py:10-20 lazy-loads difflet.backends.<hw>.ops_impl.<module>).
  • Trainium impl at difflet/backends/trainium/ops_impl/mx.py.
  • Calibration loop in difflet/pipeline/difflet_pipeline.py next to the existing from_pretrained flow (line 44).
  • Per-model precision_schedule.py next to each application.py.
Rough cost

5–7 working days, gated on M5.D1

08

Single tile → megakernelRealistic NKI Kernel Roadmap

M5.D1 closed 2026-05-14 (cclogs/m5-latent/49–54) at single-tile scope: 174 LoC across 2 @nki.jit kernels (matmul_mx_single_tile_kernel, quantize_mx_e4m3_single_tile_kernel), each wrapping a single Tensor Engine instruction. Real Trainium NEFF compile + load + forward all PASS at cosine 1.0000050 vs CPU reference.

Production DiT shapes are several orders of magnitude larger. LTX-2 480p attention is Q=K=51275; HV-1.5 480p is similar. A single-tile kernel handles 128×512×512 — ~625 tile calls per matmul when tiled naively. The roadmap below scales from current single-tile primitives to the megakernel scope described in the research plan §06 (docs/Trainium Latent Review …).

Megakernel scope (the 5 fused kernels)

Per research plan §06 "5 NKI kernels to design", Difflet's megakernel deliverable is these five fused video-DiT kernels. They are the productized M5 outcome:

KernelPurposeTrn3 features used
latent_compact_nkiSWDGE gather, N → k survivors across [T, H, W, C]dma_copy + oob_mode.skip + unique_indices + SBUF Read-Add-Write
latent_topk_nkicandidate top-k score on N, cross-chip reducereuse NKI Library Top-K Reduce + nki.collectives.all_reduce
latent_quant_dequant_nkionline MX quantization fused with TensorE matmulquantize_mx + nc_matmul_mx + BF16 PSUM (extends M5.D1.x)
fused_adaln_attn_nkiDiT block: AdaLN modulation + 3D attention with fast exp softmaxexponential + BF16 PSUM accumulation + background transpose
latent_scorer_nkiV-JEPA-style L1/L2 energy (predict vs goal latent), on-chipVectorE reduction + intra-LNC all_reduce

Why Difflet doesn't need mlp_tkg_b2 scale

/home/ubuntu/nki-moe-bin/mlp_tkg_b2 is a 4488-LoC LLM token-generation MoE MLP (one of 53+ @nki.jit files in that competition codebase). That's a different workload class:

  • TKG (token generation) — single query (Q seq=1) × long KV (K seq=N) with KV cache reuse; optimized for autoregressive inference.
  • CTE (context encoding) — many-token attention (Q=K=N), no KV cache, batched. This is Difflet's diffusion path.

Difflet stands on existing nkilib for universal kernels:

  • Attention → nkilib.core.attention.attention_cte (already in use)
  • QKV → nkilib.core.qkv.qkv
  • Output projection → nkilib.core.output_projection.output_projection_cte
  • Cumsum → nkilib.core.cumsum.cumsum

Difflet only writes the video-diffusion-specific kernels (the 5 above). Estimated Difflet first-party NKI final surface: ~2500–3500 LoC, not ~5000. Matching mlp_tkg_b2 tuning depth is an optional follow-on, gated on whether a specific performance claim demands it.

Stop conditions

  • If M5.4 mixed-precision schedule on LTX-2 / HV-1.5 hits the cosine ≥ 0.999 + wall ≤ 1.3× pure BF16 target with only multi-tile MX matmul + quantize, do not enter the megakernel phase. Fusion is contingent on M5.4 evidence that further fusion is necessary.
  • Each of the 5 fused kernels is independently triggered, not bundled. If fused_adaln_attn_nki alone closes the wall-clock gap to FA-3 on H100, do not write the remaining four.
  • Production optimization phase is never auto-entered. Only proceed if MLSys / ASPLOS reviewer demand or production SLA demands it.

M5.D1 single-tile is the floor (today, 174 LoC). Megakernel = the 5 fused video-DiT kernels (2–3 months, ~2500–3500 total LoC) is the productized M5 ceiling. mlp_tkg_b2-level optimization (~5000 LoC) is optional luxury, not the target.
