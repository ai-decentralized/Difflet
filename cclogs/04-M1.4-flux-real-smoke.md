|---|---|
| text_encoder | ✅ 2.0 MB |
| text_encoder_2 | ✅ 3.7 MB |
| transformer | ✅ 39 MB |
| **decoder** | ❌ 只有 `neuron_config.json`（6.5 KB）|

3/4 组件成功，decoder 漏了。`/tmp/nxd_model/decoder/` 也只有 `hlo_module.pb`，没 `.neff`，没 `metaneff.pb` —— 编译流程在 NEFF 阶段被打断。

### 2.2 真实 race condition

NxDI 上游 `_compile_component`（forked at `nova/models/flux/application.py`）原始代码：

```python
def _compile_component(self, component, component_name, compiled_model_path, compiler_workdir, debug):
    component_path = os.path.join(compiled_model_path, f"{component_name}/")
    if os.path.exists(component_path):       # ★ race-prone
        logger.info(f"{component_name} already compiled at {component_path}, skipping compilation.")
    else:
        os.environ["BASE_COMPILE_WORK_DIR"] = os.path.join(compiler_workdir, component_name)
        component.compile(component_path, debug)
```

机制：
1. 4 个 torchrun rank 同时跑 `app.compile()`
2. 每个 rank 串行处理 4 个 component
3. 进入 component compile → `NeuronApplicationBase.compile()` 在 component_path 下**早早写 `neuron_config.json`**（在真正的 NEFF compile 前）
4. 这一刻其他 rank 看到 `os.path.exists(component_path) == True` → 跳过该组件
5. 但 SPMD 编译需要所有 rank 一起 trace → 跳过的 rank 离开了，正在编的 rank 等不到 peer，silently 退出

为什么 text_encoder/text_encoder_2/transformer 没炸：4 rank 进入第一个 component 时是同步的（barrier 般的 lockstep），都看到目录不存在，都进入 compile。三个组件都 OK。**但到第 4 个 component 时 4 ranks 已 desync**（处理速度差异），race 触发。

### 2.3 修复

**`nova/models/flux/application.py`**（fork 文件，banner Modifications 块更新）：

```python
def _compile_component(self, component, component_name, compiled_model_path, compiler_workdir, debug):
    component_path = os.path.join(compiled_model_path, f"{component_name}/")
    # Nova fork: 检查 model.pt（终点产物），不是目录
    compiled_marker = os.path.join(component_path, "model.pt")
    _spmd_barrier()  # ← 进入前 barrier，所有 rank 同时决定
    if os.path.exists(compiled_marker):
        logger.info(f"{component_name} already compiled at {component_path}, skipping compilation.")
    else:
        os.environ["BASE_COMPILE_WORK_DIR"] = os.path.join(compiler_workdir, component_name)
        component.compile(component_path, debug)
    _spmd_barrier()  # ← 退出后 barrier，所有 rank 同时进下一个 component


def _spmd_barrier() -> None:
    """torch.distributed.barrier() if PG initialized, else no-op."""
    try:
        import torch.distributed as dist
        if dist.is_available() and dist.is_initialized() and dist.get_world_size() > 1:
            dist.barrier()
    except Exception:
        pass
```

两处变更：
- **检查 `model.pt`** 而不是目录：因为 `model.pt` 是 `NeuronApplicationBase.compile()` 完整结束后才写的。`neuron_config.json` 在前期写，不能当 marker
- **前后 barrier**：4 rank 同时进、同时出，避免 desync

### 2.4 我自己引入的 bug + 修复

第一次写 `_spmd_barrier`时定义在 class 内的 compile() 方法之后，结果 **`def load(self, ...)` 和 `def __call__(self, ...)` 顶到了 `_spmd_barrier` 函数体内**，变成 Python 嵌套函数。`NeuronFluxApplication` 类丢了 `load` 和 `__call__` 方法。

B3 第一跑就报：
```
AttributeError: 'NeuronFluxApplication' object has no attribute 'load'. Did you mean: 'float'?
```

修复：把 `_spmd_barrier` 移到 **class 之外**（module 末尾），`load`/`__call__` 回到 class 体内。`hasattr` 验证：

```python
>>> from nova.models.flux.application import NeuronFluxApplication
>>> all(hasattr(NeuronFluxApplication, m) for m in ['compile', 'load', '__call__'])
True
```

## 3. B3：forward + 出图（**阻塞**）

### 3.1 现象

```bash
torchrun --nproc_per_node=4 ... --prompt "a cat" --output /tmp/flux_smoke.png
```

加 `NEURON_RT_LOG_LEVEL=INFO` 跑后 log：

```
INFO:Neuron:Sharding weights on load...           ← 4 个 component 各自 init parallel state
INFO:Neuron:Sharding weights for ranks: 0...3
> initializing tensor model parallel with size 1   ← CLIP/VAE 用 tp=1
> initializing data parallel with size 4
[reinit again with tp=4 for T5/transformer]
INFO:Neuron:Done Sharding weights in 0.27s   × 4   ← 所有 4 component 都 sharding 成功
terminate called after throwing an instance of 'c10::Error'  ← 立刻崩
```

崩点：4 个 sub-component **各自的 `.load()` 全部完成 weight sharding 后**触发 c10::Error → SIGABRT (exit -6)。

C10::Error 没有 message（destructor 抛的），看不到具体 cause。

### 3.2 推测的原因（按可能性）

1. **多组件 warmup 冲突** — `NeuronApplicationBase.load()` 末尾会调 `warmup()` 跑一个 sample input。Flux 4 个 sub-app 各自 warmup → 多个 model 同时占 NeuronCore → c10 抛
2. **多次 `initialize_model_parallel` 残留状态** — 每个 sub-app 用不同 TP/DP 配置（CLIP tp=1 dp=4，T5 tp=4 dp=1）。重复 init 全局 PG state 可能不洁净
3. **HBM 分配冲突** — 4 component 都 load 到同一组 NeuronCore，简单累加内存够（每核 ~36 GB HBM，模型 weights ~9 GB / 核），但 NEFF runtime 可能不允许 4 个 traced_model 同时驻留

### 3.3 已加但还没验证的诊断

`examples/flux_example.py` 加了 `--skip-warmup` 标志（透传 → `NovaPipeline.from_pretrained(skip_warmup=True)` → `_load_app(skip_warmup=True)` → `app.load(skip_warmup=True)`）。

如果 c10 在 warmup 阶段，加这个 flag 应该能过。验证被 auto mode classifier 拦了，等用户决定。

### 3.4 已经验证排除的可能性

- ✅ tp/world_size 配置正确：`NovaParallelConfig(tp_degree=4)` → world_size=4 → 匹配 4 NeuronCore
- ✅ cache 命中：4 个 model.pt 都被 load 到 traced_model
- ✅ Sharding 成功：所有 4 个 `Done Sharding weights in 0.2-0.3s`
- ✅ Class 结构正确：`NeuronFluxApplication` 有 `compile/load/__call__`
- ✅ 不是 OOM：HBM 充裕，CPU 充裕（4 rank × ~30GB pipeline = 120 GB / 124 GB OK）
