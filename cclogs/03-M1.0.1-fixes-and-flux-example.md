## 1. P1-P4 修复

### P1：`NovaPipeline.compile()` 与 `from_pretrained` 一致

**问题**：`compile()` 只看 `self.compiled_path.exists()`，manifest 损坏 / 缺失时不会重编。

**修复**：`nova/pipeline/nova_pipeline.py:125`

```python
def compile(self, *, force: bool = False, debug: bool = False) -> None:
    # Use the same cache-validity check as `from_pretrained` so a stale or
    # missing manifest still triggers recompile even when the artifact dir
    # already exists.
    if force or not has_valid_manifest(self.compiled_path, self.cache_spec):
        ...
```

### P2：`dtype` 字符串归一化

**问题**：`dtype="bf16"` 和 `dtype=torch.bfloat16` 算出不同 cache key——会重复编译。

**修复**：`nova/pipeline/compile_cache.py` 加 `normalize_dtype()` + `_DTYPE_ALIASES`：

```python
_DTYPE_ALIASES = {
    "bf16": "bfloat16",       "bfloat16": "bfloat16",
    "fp16": "float16",        "float16": "float16",  "half": "float16",
    "fp32": "float32",        "float32": "float32",  "float": "float32",
    "fp8_e4m3": "float8_e4m3fn",
    "fp8_e5m2": "float8_e5m2",
}

def normalize_dtype(dtype: Any) -> str:
    if dtype is None: return "none"
    if hasattr(dtype, "__module__") and dtype.__module__ == "torch":
        return str(dtype).replace("torch.", "").lower()
    if isinstance(dtype, str):
        key = dtype.lower().replace("torch.", "")
        return _DTYPE_ALIASES.get(key, key)
    return str(dtype).replace("torch.", "").lower()
```

`CacheSpec.cache_inputs()["dtype"]` 走 `normalize_dtype(self.dtype)`。

### P3：Python 版本只取 major.minor

**问题**：cache key 含 `platform.python_version()` → `"3.12.3"`。Python 3.12.3 → 3.12.4 patch 升级会废掉所有缓存。

**修复**：`nova/pipeline/compile_cache.py:_python_version_short`

```python
def _python_version_short() -> str:
    """Major.minor only — patch upgrades do not invalidate Trainium cache."""
    return f"{sys.version_info.major}.{sys.version_info.minor}"
```

完整 patch 版本仍记录在 `manifest_metadata()["python_full"]` 供调试。

### P4：把 `model_path` 移出 cache key 输入

**问题**：cache key 含已解析的 `model_path` → 不同机器、不同 HF cache 目录的同一模型 cache key 不同 → 跨机 cache 共享（plan M5 的 S3 后端）失败。

**修复**：拆 `CacheSpec` 为两段：

```python
def cache_inputs(self) -> dict:    # ★ 进 hash
    return {
        "model_id":   self.model_id,
        "model_name": self.model_name,
        "revision":   self.revision,
        "parallel":   self.parallel.to_cache_dict(),
        "dtype":      normalize_dtype(self.dtype),
        "shape":      {"height": ..., "width": ..., "num_frames": ...},
        "toolchain":  _cache_relevant_toolchain_versions(),
    }

def manifest_metadata(self) -> dict:   # 仅写盘，不进 hash
    return {
        "model_path":  self.model_path,
        "python_full": sys.version.split()[0],
    }
```

新 manifest 格式：

```json
{
  "schema_version": 1,
  "cache_key": "...",
  "cache_inputs": { ... },     ← has_valid_manifest 比较这个
  "metadata":     { ... }      ← 仅记录
}
```

`has_valid_manifest()` 只比较 `cache_inputs`，并多了 schema_version 检查（不一致也算 miss）。`MANIFEST_SCHEMA_VERSION = 1` 显式版本，未来字段调整可以 bump 强制全量重编译。

附带改进：`read_manifest()` 把 `OSError`/`json.JSONDecodeError` 当 cache miss（之前会 raise），更稳健。

## 3. `examples/flux_example.py`

新增 200 行的 argparse-driven Flux 推理脚本。设计要点：

### 3.1 调用范例（docstring 顶部）

```bash
# 全 8 卡 prod
torchrun --nproc_per_node=8 examples/flux_example.py \
    --model black-forest-labs/FLUX.1-dev \
    --tp-degree 8 --prompt "..." --output out.png

# 4 核 dev box (本机 trn3pd98.3xlarge)
torchrun --nproc_per_node=4 examples/flux_example.py \
    --model black-forest-labs/FLUX.1-dev \
    --tp-degree 4 --prompt "..." --output out.png

# CFG parallel (world_size 翻倍)
torchrun --nproc_per_node=8 examples/flux_example.py \
    --model ... --tp-degree 4 --cfg-parallel \
    --negative-prompt "..." --true-cfg-scale 5.0 --output ...

# 仅预编译 cache warmup
torchrun --nproc_per_node=4 examples/flux_example.py \
    --model ... --tp-degree 4 --precompile-only
```

### 3.2 设计取舍

- **`--tp-degree` 默认 None**：未传时 `_build_parallel_config` 返回 None，`NovaPipeline.from_pretrained` 走 registry 默认（`flux` entry 是 `tp_degree=8`）。这样不强制覆盖框架默认。
- **rank 0 only 写 output**：`_is_main_process()` 兼容 `torch.distributed` / `RANK` env，不在每个 rank 上重复写文件。
- **timing markers**：分别打 `from_pretrained` 和 `forward` 阶段耗时，便于一眼看 compile cache 是否命中（命中时 from_pretrained 几秒；miss 时分钟级）。
- **`--precompile-only` mode**：调 `NovaPipeline.precompile`（= `from_pretrained(load=False)`），CI / cache warmup / benchmark 前置准备用。
- **`--debug-compile` / `--force-compile`**：透传 NovaPipeline 同名参数，不再额外封装。

### 3.3 验证

`--help` 输出正确；`compileall` 通过。**未在硬件上跑真 Flux**（需要 50GB 模型下载 + 10+ 分钟 compile），但 `argparse` + 模块 import 路径已在 4.1 节验证。

## 4. 真硬件验证

### 4.1 Manual smoke 脚本

`tests/manual/check_neuron_init.py`（86 行），不下载模型、不触发 AOT compile，只验证：

1. torch_neuronx + torch_xla 在 torchrun 多进程下 init 干净
2. 每个 rank 拿到 `xla_device`
3. 跑一个 `t * 2 + 1` 验证 XLA runtime 真活
4. `nova` top-level + `Flux` Neuron application 模块在多进程上下文下 import 通过

**Pass**。两个 rank 都跑通了。

### 4.3 关键观察

1. **系统级 Neuron NEFF 缓存** 在 `/var/tmp/neuron-compile-cache/<neuronxcc-version>/MODULE_*/model.neff`。rank 0 编了 `t*2+1` 这个图，rank 1 直接命中。**Nova 的 `~/.cache/nova/` 是这个缓存的高层：**
   - Nova cache：`(model_id, parallel, shape, dtype, toolchain)` → AOT 编译结果目录
   - Neuron NEFF cache：每个 HLO 模块 → NEFF 二进制
   - 两层独立、互补；Nova 失效时 Neuron cache 仍然能加速 sub-graph 重编。

2. **EFA 未配置**：
   ```
   CCOM WARN NET/OFI Failed to initialize rdma protocol
   net_plugin.cc:97 CCOM WARN OFI plugin initNet() failed is EFA enabled?
   ```
   单实例无影响，多机 Wan/Hunyuan TP > NeuronCore-per-instance 时需要 EFA。先记下，到 M3 (HunyuanVideo) 之前需要 ops 配置。

3. **几个 deprecation 警告**（都是 NxDI / torch_xla 升级路径，不阻塞）：
   - `xm.xla_device()` → `torch_xla.device`
   - `xm.mark_step()` → `torch_xla.sync`
   - `torch_neuronx.nki_jit` → `nki.jit`（在 NXD 内部，不是我们的代码）
   - MoE blockwise kernels 缺失（diffusion 用不到）

4. **冷启动开销**：rank 0 第一次跑（含 NEFF 编译）13.9s；rank 1 命中 cache 也用了 15.3s（因为它要等 rank 0 init + 自己也走 import 闭包）。这是 **import 重 + 第一次 XLA lower 的固定成本**。Flux compile 上叠加这个 baseline。
