# Lessons

- A staged CLI topology is not automatically a valid resident-serving topology. Before co-loading stages in one Neuron process, verify that their NxD `world_size` values match or compile a serving-specific artifact with a uniform world size; process-level core reservation alone does not make mixed TP safe.
- Do not turn optional, model-specific calibration metadata into a generic serving startup schema. Transport raw options to the selected adapter and let it parse only fields that model uses; ignore calibration paths when acceleration is disabled, but fail startup when explicitly enabled calibration is invalid.
- Optional serving acceleration config must be resolved only when its enable flag is explicit, then validated and frozen before worker spawn; replacement workers must not reopen the user's mutable source file.
- Runtime allocation contracts are incomplete until the spawned child applies exact core, virtual-core, logical-NC, and distributed environment values before model imports; tests must observe those values inside a real spawned worker.
- Multiprocessing replica rank is not the XLA global ordinal. Measured on a v5litepod-4: worker 0 -> ordinal 2, 1 -> 0, 2 -> 3, 3 -> 1. Anything that names a rank across processes — a collective's root, "who owns the encoder" — must use `xr.global_ordinal()`, while anything the engine keys off its own replica index must use that. Choosing the wrong one does not fail: it broadcasts a zero placeholder and merely changes the output.
- A stage that runs on every replica must be pure compute. Replicas execute identical work so the sharded model's collectives complete, but a stage that also touches something outside its process — media in the request's storage, a socket, a counter — must ask whether it is the primary replica. Four replicas writing the same request's staging file produced three tracebacks per request *after* the engine reported success, and three redundant host decodes competing for the same CPU.
- Never raise before a collective. Every other rank is already committed to reaching it and will block until the engine's cancel timeout. Convert the failure to a status, broadcast it with the payload, and re-raise identically on every rank — otherwise a validation error reachable from user input becomes a hang.
- A fused attention kernel may accept an unaligned sequence length and pad it with zeros that then join the softmax. At Wan's 4680 that is 5.4e-2 relative error against 2.8e-3, with nothing raised and images that still look plausible. Pad to the kernel's block size and mark the pad rows with segment ids; it costs nothing measurable.
- Under lazy XLA an unsynced inter-step delta measures how fast Python *enqueues*, not how long the device takes — the backlog is paid at the loop's final sync. Reported as device time it produced a per-step figure smaller than the model's own attention. Cross-device per-step numbers must be device-synced, which is what every other device folder does; report the unsynced basis alongside, never instead.
- Validate a numerical port against the upstream implementation at the *same dtype*, not only against fp32. Comparing bf16 to fp32 conflates "our implementation is wrong" with "bf16 costs this much" — for Wan, upstream's own bf16 forward scores 0.99873 against its own fp32, so an absolute 0.999 gate fails upstream itself and says nothing about us.
